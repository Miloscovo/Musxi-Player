# CEF Windows x64 dependency and license evidence

Audit date: 2026-09-29. This note records the CEF binary distribution consumed by the current Windows build and the runtime files selected by the installer. It does not claim that Musxi Player builds Chromium from source: CMake consumes the prebuilt CEF SDK through `CEF_ROOT` and links the application's CEF target against the SDK libraries.

## Version and packaging evidence

`build/cef-msvc/CMakeCache.txt` resolves `CEF_ROOT` to `D:/develop/cef_binary_152.0.6+g708dc14+chromium-152.0.7977.83_windows64`. That SDK's `README.txt` identifies itself as the **Standard Binary Distribution for Windows** and records:

- CEF `152.0.6+g708dc14+chromium-152.0.7977.83`, CEF commit `708dc140cbc3286826a8abef89dc23a44ff9ea72`.
- Chromium `152.0.7977.83`, Chromium commit `79460ebecaa5625e57a5fb679a735659e73dc687`.
- The matching `include/cef_version.h` is present in that SDK.
- The official CEF CDN serves [`cef_binary_152.0.6+g708dc14+chromium-152.0.7977.83_windows64.tar.bz2`](https://cef-builds.spotifycdn.com/cef_binary_152.0.6%2Bg708dc14%2Bchromium-152.0.7977.83_windows64.tar.bz2); its published `.sha256` sidecar is `a32f0f552112825b2b63fc127c96c09b2b14de8f9b968a1169385bf93021eba4` (asset size 359,617,808 bytes, last modified 2026-09-07). I downloaded the archive to a temporary audit workspace and verified that its SHA-256 equals the official sidecar.

The exact upstream CEF source references are [CEF's versioned Windows redistribution README](https://github.com/chromiumembedded/cef/blob/708dc140cbc3286826a8abef89dc23a44ff9ea72/tools/distrib/win/README.redistrib.txt), [CEF build-argument helper](https://github.com/chromiumembedded/cef/blob/708dc140cbc3286826a8abef89dc23a44ff9ea72/tools/gn_args.py), and Chromium's [versioned DEPS](https://github.com/chromium/chromium/blob/79460ebecaa5625e57a5fb679a735659e73dc687/DEPS).

`installer/MusxiPlayerUpgrade.iss` copies `Release\*.dll` excluding `MusxiPlayerWeb.dll` and, since 2026-09-30, `d3dcompiler_47.dll`, `Release\*.pak`, `icudtl.dat`, `v8_context_snapshot.bin`, `vk_swiftshader_icd.json`, locales, `licenses\*`, and `THIRD_PARTY_NOTICES.md`. I extracted the official archive's `LICENSE.txt`, `CREDITS.html`, and all nine CEF runtime DLLs listed below; all eleven SHA-256 values match the configured SDK copies (zero mismatches). This establishes that the inspected CEF license/credits and packaged CEF DLLs are byte-identical to the checksum-verified official standard distribution.

## FFmpeg embedded in CEF is separate from the app's FFmpeg DLLs

The application also ships the separately audited BtbN FFmpeg DLLs listed in `THIRD_PARTY_NOTICES.md`. Those files are **not** the FFmpeg implementation bundled by Chromium inside `libcef.dll`, and their LGPL-3.0+ build configuration must not be used to infer the CEF codec configuration.

Chromium's exact `152.0.7977.83` [DEPS file pins `src/third_party/ffmpeg` to commit `2b68d2babae73714846961fb0ee47e3b3d2e39a9`](https://raw.githubusercontent.com/chromium/chromium/152.0.7977.83/DEPS); the corresponding [official Chromium FFmpeg source revision](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/2b68d2babae73714846961fb0ee47e3b3d2e39a9/) is confirmed. That exact source tree has [`COPYING.LGPLv2.1`](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/2b68d2babae73714846961fb0ee47e3b3d2e39a9/COPYING.LGPLv2.1), [`LICENSE.md`](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/2b68d2babae73714846961fb0ee47e3b3d2e39a9/LICENSE.md), [`README.chromium`](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/2b68d2babae73714846961fb0ee47e3b3d2e39a9/README.chromium), [`BUILD.gn`](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/2b68d2babae73714846961fb0ee47e3b3d2e39a9/BUILD.gn), `ffmpeg_generated.gni`, and Chromium's `chromium/` configuration/patch material. The pinned `README.chromium` labels this as Chromium's shipped FFmpeg fork and declares `bsd-2-clause`, `bsd-3-clause`, `isc`, `lgpl-2.1`, and `mit`; it points to the GN target, platform configurations, and downstream patches needed for a corresponding-source review. The exact CEF credits say FFmpeg is LGPL v2.1-or-later by default, while optional parts can switch the license to GPL v2-or-later when explicitly enabled.

The CEF build-argument helper at the pinned CEF commit sets `is_component_build=false` for binary distributions and accepts overrides through `GN_DEFINES`; it does not itself set `ffmpeg_branding` or `proprietary_codecs`. Google's [CEF build instructions](https://support.google.com/webdesigner/answer/10043691?hl=en) state that CEF's default build does not enable Chrome's proprietary audio/video codecs and that enabling them requires `ffmpeg_branding=Chrome proprietary_codecs=true`, together with codec-patent licensing agreements/fees. Since the local SDK is byte-identical to the official **Standard Binary Distribution**, this is evidence for the standard default: embedded FFmpeg is expected to be LGPL v2.1-or-later, with no evidence of GPL or nonfree options. The archive contains no `args.gn`, GN log, or build manifest, so the optional feature flags are not independently recorded alongside the binary.

That same CEF helper sets `enable_widevine=true`, but neither the inspected CEF SDK `Release/` tree nor the application's CEF `Release/` output contains a standalone `widevine*` or `*cdm*` payload. The installer file rules therefore do not package a Widevine CDM binary. This finding is limited to files selected from the inspected SDK; if a CDM is separately added or downloaded for a release, audit its own proprietary license and distribution terms.

The archive provenance uncertainty is closed: the official sidecar checksum matches, and the package files selected for the application match the configured SDK byte-for-byte. The exact official CEF build arguments are not published inside this archive, so the optional codec flag conclusion rests on the verified standard-distribution provenance and CEF's published default-build instructions rather than a per-binary GN manifest.

Because FFmpeg is embedded in `libcef.dll` and the installer does not include CEF/Chromium source or linkable object outputs, the LGPL corresponding-source/relinking obligations for the CEF FFmpeg build remain a release/legal review item. The exact source commit and official license/build-source paths are identified. The complete commit tree was fetched from the [chromiumsrc/ffmpeg GitLab mirror](https://gitlab.com/chromiumsrc/ffmpeg/-/commit/2b68d2babae73714846961fb0ee47e3b3d2e39a9); Git verified `FETCH_HEAD^{commit}` equals Chromium's pinned commit `2b68d2babae73714846961fb0ee47e3b3d2e39a9`. The 18,560,293-byte archive has SHA-256 `44e2a979772d63070dd354d22e32aecd209ec5689ea738c8ef81185fee3ebcfb` and a local sidecar under ignored `build/cef-ffmpeg-source-materials/`; these generated materials are not committed to the repository. `package.ps1` checks the exact commit in its GitLab fallback, verifies the source/license/build entries, and stages it as a companion release asset. The app's separate [FFmpeg-LICENSE.txt](FFmpeg-LICENSE.txt) covers the BtbN build and is not a substitute for CEF's corresponding source and applicable modifications/build instructions.

## Build inputs not shipped

The project consumes the prebuilt CEF standard binary SDK; it does not build the Chromium source tree as part of `build.ps1`. The CEF SDK headers, import libraries, CMake files, and the MSVC/Windows SDK toolchain are build inputs rather than packaged runtime dependencies. The installer excludes build tools and symbols; it only includes the runtime files selected in its `[Files]` section.

## Review results and remaining release action

1. **CEF provenance — verified.** The official CEF CDN archive's published SHA-256 matches the downloaded archive, and `LICENSE.txt`, `CREDITS.html`, and the nine installer-selected CEF DLLs match the configured SDK with zero SHA-256 mismatches. The feature-flag conclusion remains scoped to the official standard distribution because the archive does not include its GN argument manifest.
2. **CEF-embedded FFmpeg LGPL — source acquisition is resolved; full corresponding-source/relink review remains.** The exact source tree has been obtained from a GitLab mirror and its fetched Git object ID matches Chromium's pinned commit. The archive and SHA-256 are in the ignored `build/cef-ffmpeg-source-materials/` directory; `package.ps1` will stage both beside the installer. This closes the missing-source-material gate, but this review does not decide whether the archive alone fully satisfies distribution/relinking requirements for the exact CEF binary. Inspect the generated companion asset and have that LGPL conclusion reviewed before release. The BtbN source bundle does not replace this separate CEF source.
3. **Microsoft `d3dcompiler_47.dll` — publisher confirmation recorded.** Microsoft Learn allows the unmodified compiler DLL to ship side-by-side with an application. The inspected CEF DLL is version `10.0.26100.7705` with a valid Microsoft signature. The installed Windows SDK agreement is `C:\Program Files (x86)\Windows Kits\10\Licenses\10.0.26100.0\sdk_license.rtf`; its Distributable Code section requires significant primary functionality, terms protecting Microsoft at least as much as the SDK agreement, and a publisher indemnity/defense commitment. The original agreement is copied without modification to [Microsoft-Windows-SDK-LICENSE.rtf](Microsoft-Windows-SDK-LICENSE.rtf), SHA-256 `0F4A26AC9DC50066F8A1BFEAAF3F092D1B9E4791DF5487B9F3C31E7C3DC4D7F5`. Both installer scripts display and install the agreement. On 2026-09-29, the user confirmed they can represent the publisher and accept the downstream and indemnity/defense obligations. This records that confirmation; it is not an independent legal opinion on whether the agreement applies to this distribution or whether the downstream terms are adequate. This is a proprietary-license item, not a code/build failure. The project's own `LICENSE` was unchanged during the original 2026-09-29 audit and was subsequently migrated to GPL-3.0-or-later at the user's request.

No C++ or CEF bridge code was changed for this audit.
