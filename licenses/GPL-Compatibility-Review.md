# GPL-3.0-or-later compatibility review

Review date: 2026-09-30. Scope: the Microsoft D3DCompiler redistributable and the statically linked MSVC runtime. These findings distinguish GPL compatibility from Microsoft's independent permission to use and redistribute its software. They do not declare the current installer ready for a GPL release.

## D3DCompiler

The previous installer included the CEF SDK's proprietary `d3dcompiler_47.dll`, version `10.0.26100.7705`, SHA-256 `A05F99734F7C4822FEFC12B367AF21FD0976ED6608752FB1E1E80B6ECE7ECBBB`. The previous installer scripts also displayed the Microsoft Windows SDK agreement as the installation agreement. Publisher acceptance of that agreement does not itself establish GPL compatibility.

Microsoft's [current DirectX deployment guidance](https://learn.microsoft.com/en-us/gaming/gdk/docs/features/common/packaging/packaging-framework-packages?view=gdk-2604) explicitly identifies D3DCompiler as included in Windows 10. The earlier statement that this DLL is categorically not an OS component was too broad. Both installer scripts target Windows 10 or later (`MinVersion=10.0`).

An isolated copy of the existing Release output was created at `build/license-migration/cef-system-d3d`, excluding `d3dcompiler_47.dll`, runtime/service directories, caches and build symbols. Running `MusxiPlayerWeb.exe --test-app --cef-smoke` returned exit code **0**. Process-module observation during this run recorded **`C:\windows\SYSTEM32\D3DCompiler_47.dll`**. The system DLL has version `10.0.26100.1000`, a valid Microsoft Windows signature and SHA-256 `89611F606AA529E82C08B9CE36DF9870D844BC8C3843449B5308C145B99A3443`.

This verifies CEF startup, rendering and the existing React/native bridge smoke checks using the system DLL on this machine. It does not establish compatibility on every Windows 10 build, GPU or driver, nor test cloud playback. No production binary, CMake setting or installer was changed.

Recommended release approach: use the Windows-provided component, validate on the supported Windows/GPU configurations, and exclude the application-local compiler DLL from packaging. Review the installer agreement screen so Microsoft terms are not imposed on Musxi Player's GPL-covered code. Preserve relevant third-party notices; do not relicense Microsoft code. Implemented on 2026-09-30: both installer scripts exclude the application-local DLL, delete an old copy from `{app}` during upgrade, and display the project GPL license. Original Microsoft license texts remain unchanged. The CEF SDK and development output still retain their original DLL; the exclusion is confined to distribution.

## MSVC static runtime

Installed toolchain: Visual Studio Build Tools 2026 `18.10.12210.168`, `isPrerelease=False`; MSVC tools directory `14.51.36231`, compiler/dumpbin version `14.51.36257.0`; Windows SDK `10.0.26100.0`. The configured Release target uses `MultiThreaded` (`/MT`); Debug uses `/MTd` and is not the intended release configuration. `dumpbin /dependents` on the existing `MusxiPlayerWeb.exe` and `MusxiPlayerWeb.dll` lists no separate MSVC runtime DLL dependency.

GPLv3 section 1 includes qualifying libraries normally supplied with the compiler in its System Libraries definition. GNU's [System Libraries FAQ](https://www.gnu.org/licenses/gpl-faq.html#SystemLibraryException) expressly permits distribution of a linked executable containing qualifying proprietary system libraries. Consequently, static linking alone is not evidence of GPL incompatibility. This assessment is confined to the normal compiler runtime, not arbitrary proprietary libraries.

Microsoft's [licensing guidance](https://www.microsoft.com/licensing/guidance/Visual-Studio) permits distribution of the linked output of code identified as distributable `.lib` files; it does not grant permission to redistribute every library in an installation. The installed `Licenses/2052/Redist.txt` points to the [2026 redistribution list](https://learn.microsoft.com/en-us/visualstudio/releases/2026/redistribution), which conditions redistribution on a valid product license and excludes preview and debug-nonredistributable components.

The exact official [2026 Build Tools agreement](https://visualstudio.microsoft.com/license-terms/vs2026-ga-diagnostic-buildtools/) requires a valid Visual Studio product license for developing the application's own code. Its no-product-license exception addresses third-party OSI-approved open-source dependencies, not an unrestricted right to develop any application. The separate [V14 Runtime agreement](https://visualstudio.microsoft.com/license-terms/vs2026-ga-visualcpp-v14-redist-runtime/) grants installation/use rights; it is not by itself a general redistribution grant. The official embedded DOCX documents were retrieved unchanged into ignored `build/license-migration/` for inspection, not added to the installer.

Publisher confirmation recorded on 2026-09-30: the user stated that they develop Musxi Player as an individual developer, have installed Visual Studio Community 2026, and have read and accepted its license terms. The [Community 2026 agreement](https://visualstudio.microsoft.com/license-terms/vs2026-ga-community/) permits individual developers to develop their own applications. This closes the outstanding publisher-entitlement declaration on the basis of the user's statement; it is not independent verification of their account or licensing history and does not retroactively establish authorization for earlier builds. The release binary should be rebuilt under the confirmed authorization before publication. No additional GPL linking permission has been added, and no switch to `/MD` is justified solely by the GPL question. The D3DCompiler packaging adjustment above is implemented; its broader platform-test limitations remain applicable.
