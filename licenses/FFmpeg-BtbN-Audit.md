**Workspace inventory (2026-10-01).** The ignored SDK under `build/deps/ffmpeg-n9.0.2-3-ga5923073bf-win64-lgpl-shared-9.0/` contains seven FFmpeg DLLs, `ffmpeg.exe`, `ffprobe.exe`, `ffplay.exe`, seven MSVC import `.lib` files, seven MinGW `.dll.a` import files, export `.def` files, headers, pkg-config metadata, documentation and `LICENSE.txt`. The SDK ZIP and exact-source archives are build/source inputs. Only the four playback DLLs enter the application. Matching four-DLL copies were found in `build/cef-msvc/src/cef/Release/`, `build/cef-msvc/Release/`, `build/audio-a2/Release/`, `build/license-migration/cef-system-d3d/` and the extracted 0.2.0 installer; all match the pinned ZIP hashes. FFmpeg wrapper source/object files belong to Musxi Player and are not independent third-party FFmpeg binaries.

`build/video-tools/av.libs/` is an unrelated local PyAV 18.1.0 wheel's FFmpeg 8.1.2 toolchain (seven FFmpeg DLLs plus external dependencies); no tracked source/build/package reference or installer rule includes it. Its APIs report LGPL version 3 or later, but its configuration enables x264/x265 without an `--enable-gpl` flag. The precise wheel build/source/license election is **not established** by those strings; review manually before ever redistributing this toolchain. It is not the application's BtbN SDK. Cached extension files `cef-cache/.../xl-player/lib/libffmpeg.wasm` and `libffmpeg.js` are local browser-cache content, unreferenced by the source and excluded by the installer's non-recursive root DLL selection; their version/source/license is **unknown**, and they must not be added to a portable package. A portable release must use an explicit clean runtime inventory, never zip the entire development output including caches/PDBs/test state.

**Dynamic linking and replacement.** `cmake/FindFFmpeg.cmake` creates SHARED IMPORTED targets with import libraries; the actual host DLL's PE import table references precisely the four DLLs above. The STATIC decoder target contains Musxi's wrapper, not a static FFmpeg library. Close the application, back up the application-local DLLs and replace all four with an ABI-compatible Windows x64 shared set exporting the APIs used by Musxi. The existing decoder checks ABI major versions (63/63/61/7), not hashes, signatures or vendor identity. No new runtime integrity restriction has been added. Source/notice hash checks run only during SDK setup, CMake configuration, builds and packaging; they enforce publisher inventory, not recipient DLL selection.

**Additional copyright attribution.** This software is based in part on the work of the Independent JPEG Group. Original FFmpeg JPEG-derived files and their notices are preserved in the external-notice collection.

**Source availability and limits.** `package.ps1` stages the bundle as `MusxiPlayer-FFmpeg-Source-Materials-0.2.zip` with its checksum beside the installer. The installer does not embed it, and local staging does not establish public availability: the publisher must actually provide matching materials with a release through an applicable license distribution method. The bundle README records missing post-`cargo update cc` resolution/log and mutable Docker image digests. The matching successful BtbN build job and release-API digest are now identified. These provenance limits and the exact remaining external-notice/source/relinking cases are documented in [FFmpeg-Follow-up-Review.md](FFmpeg-Follow-up-Review.md). The public release API currently exposes no published 0.2.0 source assets. Do not claim bit-for-bit reproducibility or unconditional release clearance.

Replacing BtbN DLLs does not replace CEF's embedded FFmpeg. `package.ps1` separately stages the pinned Chromium FFmpeg source archive; it is not a complete Chromium/CEF rebuild kit.

**Release checks.** [verify-ffmpeg.ps1](verify-ffmpeg.ps1) verifies SDK file/header/license hashes, the CEF `libcef.dll` hash, notice version/commit/build/hash fields and the staged four-DLL inventory. Official packaging additionally checks both source assets against repository-pinned checksums. Both installer definitions already include `THIRD_PARTY_NOTICES.md` and recursively copy `licenses/`; CMake now stages the same notices/licenses for the native output used as a portable layout. These checks do not certify legal compliance, inspect an installed user's replacement DLLs or publish source materials. When updating FFmpeg, re-audit the new DLLs/configuration/source and update the manifest and this single record together. Existing installer EXEs must be regenerated to contain the new texts.
