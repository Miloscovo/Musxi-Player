# 定时停止接线合同

状态：2026-11-08 服务管理增量。旧分钟入口继续工作；新模式先提供后端接口，CC 增补选项，不重做菜单布局。

## 入口

`app.playback.sleepTimer: StateFlow<SleepTimerState>` 为当前进程播放服务的事实状态；`active`、`mode`、`phase`、`deadlineElapsedMs`、`revision` 不含歌曲私有票据。计时基于 `SystemClock.elapsedRealtime`，包含暂停与缓冲时间；页面关闭不取消。

| 命令 | 行为 |
| --- | --- |
| `startSleepTimer(minutes, finishTrack=false, callback)` | 1–1440 分钟，到点立即暂停；旧15/30/45/60/90分钟入口已接此命令 |
| `startSleepTimer(minutes, finishTrack=true, callback)` | 到点绑定当时实际队列槽位，播完该首再暂停；到点无可完成曲目则直接暂停 |
| `stopAfterCurrentTrack(callback)` | 绑定当前槽位，播完该首停止；未就绪/已结束/出错或票据变更时拒绝 |
| `cancelSleepTimer(callback)` | 清定时与曲末门禁，不主动恢复播放 |

回调在主线程，`Result<Unit>` 成功才显示设置成功；失败提示可重试，不能只点菜单就先宣告成功。命令只接受同应用控制器；等待回执最多10秒，超时结果不保证服务未接受，界面以状态流为准，不自动重试。

## 展示

`COUNTING` 用 deadline 减当前单调时钟显示倒计时；`WAITING_FOR_TRACK_END` 显示“播完本曲停止”；`OFF` 不显示计时标记。等待曲末时无需每秒重组，暂停后仍保留标记。计时按钮以 `active` 判断，不能只看 deadline 是否为空。旧格式化函数保留，新服务替代了原 app 进程计时对象。

首版菜单保留既有分钟选项，不擅自扩充CC的UI；新增“播完本曲”和“到点后播完本曲”的入口待接线。后端已区分三种模式，不将其折成同一倒计时。

## 播放边界

- 曲末等待使用 ExoPlayer 的 `pauseAtEndOfMediaItems`，在媒体项边界暂停，覆盖顺序、随机、列表循环与单曲循环；不靠页面轮询在下一首响起后补暂停，不修改用户循环模式。
- 原队列槽位票据是绑定身份；同歌的两个重复槽位仍不同。换源、切音质、恢复原源或同槽拖进度不换绑定；拖到曲末仍按曲末处理。
- 用户跳到另一槽、删除当前槽或错误恢复跳过时，消费曲末等待并暂停。再次明确点击播放/跳转后可正常继续，不保留幽灵定时。
- 明确替换整队列取消已绑定的曲末等待；尚未到点的分钟计时跟随新队列继续。停止、清空、账号失效清队列、服务销毁取消计时，不清用户队列或最近播放来实现定时停止。
- 定时触发只暂停并保存现有检查点，同时取消延迟换源/前台门禁的继续播放意图，防止晚到回调恢复播放。仍可手动恢复播放。
- 进程/服务销毁不持久化计时；不会在次日打开时恢复过期定时。锁屏和后台服务存活时有效，CPU休眠后用elapsedRealtime重查；未新增精确闹钟或常驻唤醒锁，不能宣称进程被系统杀死仍会执行。
