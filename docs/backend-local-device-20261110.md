## 失败尝试与限制

前几轮自动化在厂商选择器/Activity 启动上超时，期间已导入的本轮记录用 marker 清理后重试；其中一次在测试包生成完成前安装到上一版，随后等待完整编译后重装。没有把这些失败尝试删掉或算作整体通过。

最终调试入口固定到设备自带 `com.android.documentsui`，传回真实 URI 与系统 flags；正式 `LocalAudioPickers` 仍不固定提供方。OPPO 文件管理器在当前浮窗/任务环境下的完整自动操作尚未通过，不能由标准选择器结果推断厂商兼容通过。

来源删除测试最初强制期望 `MISSING/NOT_FOUND`，设备提供方实际返回 null 查询，因此断言失败。按现有合同保留 `READ_FAILED` 的保守分类后，记录实际结果再验证重关联；没有为单台提供方把所有 null 当作文件不存在。

电脑首次主包/JVM预检通过；随后完整 Lint 分析耗时较长，为优先使用手机时间主动中止。完整交付以最终统一验证索引为准，不将被中止的构建记通过。

仍待：正式页面、真人听音和音声样本、M4B/章节/其他编码与提供方、大文件容量/内存、整机重启、系统回收、长时锁屏/Doze、真实电话和耳机/蓝牙切换、通知栏实际点击、壁纸选图与正式视觉。65 秒后台不能代替长后台。

## 重跑与收尾

独立存储与壁纸可明确选择 `tech.musxi.player.localaudio.LocalAudioStorageDeviceTest,tech.musxi.player.WallpaperDeviceTest`。本地链路须显式选择 `LocalAudioDeviceTest`、传 `allowLocalAudioDevice=true` 和 `localPhase`，按 `import → cold → missing → refresh → transfers → timers → background → focus → system → revoke → reauthorize → cleanup` 分阶段；删除源、force-stop 和增加替代文件是外部协调步骤，需使用新建测试目录并核对 marker，不得套用户真实文件。各阶段顺序应按当次计划选择，不能盲跑全套历史设备测试。

本轮最终清理阶段移除 marker 中的所有音频和分组、解除目录关联、收回其无人使用的授权、清空测试本地队列并保持暂停。手机测试目录内的源文件、导出和备份逐个删除后移除空目录；保留电脑样本、日志、结果和必要回退点。旧平台继续播放记录不恢复、不重建。
