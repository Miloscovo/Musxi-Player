## 实现范围

`DsfPlaybackSupport`集中现有解码器支持范围：DSD64／128／256，单／双声道，176.4kHz PCM，沿用64GiB／366天限制。容器解析仍可识别更高倍率与更多声道，但不因此声明能播放。内核和Extractor改为引用相同判断／输出常量，滤波系数、顺序、定位与补尾算法未改；单声道属于代码能力，尚未新增真实单声道听音证据。

预览、正式元数据导入共用`DsfSourceInspection`，头固定92字节，标签随机读取头10字节及最多1MiB载荷，合作取消、权限和来源前后大小／修改时间检查。坏／超限／不支持标签回退文件名，权限撤销和来源变化仍失败；不以InputStream.skip穿越音频负载。导入标题／作者接入已有ID3文本解析；专辑／曲序可在预览读取，现有通用持久元数据模型没有为它们新增字段或迁移。

预览`playbackSupported`需要应用开关、支持格式与当前文档随机读取检查同时满足。正式开关仍关闭，所以正式预览继续false；以后启用的debug验收窗口将可返回true，旧设备短样步骤先预览再打开实验gate，仍符合其断言。该字段不是播放成功票据，播放时再次读取来源。

目录枚举在开关开启后接受扩展名为`.dsf`且MIME为普通二进制的候选；关着时不新增该候选。原有audio MIME候选仍按既有枚举规则返回，元数据层最终阻止DSF导入。文件选择器沿用`LocalAudioPickers.files(showAllFileTypes=true)`作为错误MIME的选择方式，没有把所有普通文件混入默认音频列表，不修改页面。

## COPY 与 REFERENCE

REFERENCE在导入、重新关联和播放／检查来源时要求随机读取到声明的音频负载最后一字节；不能定位的来源不再仅凭“可打开”提交成功。读取全程有界，不扫描中间负载。成功只表示当时这次读取可用，不保证其他时点或所有提供方。

不可随机读取返回既有`LocalAudioError.READ_FAILED`，并附可选`LocalAudioRecoveryAction.COPY_REQUIRED`。新增可选字段：

- `LocalAudioFailure.recoveryAction`：回调失败／后端播放解析异常可读取。
- `LocalAudioImportResult.recoveryAction`：逐文件导入失败读取。
- `LocalAudioSourceCheckResult.recoveryAction`：来源检查结果读取；过期观察不附旧恢复提示。

不自动把引用改成复制、不隐式复制GB文件，不删旧条目或释放仍被引用的授权。既有页面仍显示READ_FAILED通用提示，CC后续可按恢复字段引导“复制到Musxi”；此次没有新增UI文案。底层服务当前公开播放错误仍沿用已有错误码，不另承诺通知／页面已展示该提示。

COPY允许顺序读取来源，继续沿用现有内容寻址、空间检查、临时文件、取消与事务规则。复制完成后，用私有文件的实际长度／DSF头与复制前声明比对，再核对来源版本；从私有副本随机读取有界尾部标签，补上管道来源在复制前读不到的标题／作者。副本失败时仅回收本轮新建且未被库引用的文件，保留已有内容寻址文件。不进行完整音频逐位解码校验；同大小、同头且提供方没有可靠版本字段的内容替换仍有局限，不能宣称完整防篡改。

来源检查对普通音频保留一次首字节读取；首字节为D时最多继续到4字节，识别DSD魔数后才读92字节头，DSF扩展／MIME已知而头不正确也拒绝。复制／引用的DSF点播重新确认支持范围和开关，引用再次确认随机读取及来源版本。

自动封面提取暂跳过DSF文件名候选；导入及重新关联路径对扩展或MIME识别出的DSF也不调用通用媒体封面读取。APIC实现后补，默认图／手动图沿用，用户已有手动封面不清除。
