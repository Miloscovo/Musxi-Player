# 播放器与歌词设计

更新：2026-10-23。以下样张由 Robolectric/Roborazzi 使用合成数据生成，不含设备账号；样张不代表实机验收。当前范围见 [0.1 验收](../android-0.1-acceptance.md)。

## 当前歌词页

“译”与爱心共用右侧中心线，两个独立 48dp 触摸区域不重叠，形成对应左侧歌名/歌手/平台的操作组。字标可见轮廓 24×21dp、圆角 6dp、描边 1.2dp；开启为强调色填充，关闭为灰色描边。字形按系统实际轮廓在水平和垂直方向居中，避免文字行框造成视觉偏移。

中文主体默认关闭译文，外语主体默认开启；当前实际来源的手动选择优先，译文后补或刷新不覆盖选择。无译文时禁用，获取失败与无译文区分；已有译文时可继续显示，长按独立刷新。切换显示不增加网络请求，不引入机器翻译服务。

短歌词按实测文档高度整组居中；长歌词以当前原文/译文行组的实测中心定位，首尾自然限位。翻译开关、译文后补、窗口和字号改变均重新测量；浏览时不抢回跟随。上下结构间距 20dp，渐隐只在对应方向还有内容时出现，不保留早期 96dp 尾占位或 35% 固定顶部锚点。

字体集中在 ui/theme/Type.kt，使用 Android 系统字体与 0sp 自然字距；原文 16sp/24sp，普通行 Medium、当前行 SemiBold，译文 13sp/20sp Normal。左侧信息区按内容增高，避免大字体裁平台名。已收藏使用红色实心心形，写入期间保留上次确认状态，核实成功后才改变。

## 核心约定

**七种状态只占一行。** 全部落在标题块的第三行，原位替换，200ms 淡入淡出，布局零跳动。优先级：无输出 > 播放失败 > 被其他应用暂停 > 已播完 > 平台。

| 状态 | 第三行 |
| --- | --- |
| 正常 | `网易云音乐`（全称，见下） |
| 换源后 | `QQ音乐 · 由网易云音乐提供` |
| 换源查找中 | `当前音源不可用 · 正在换源`（**中性灰，不是错误**） |
| 确实无音源 | `暂无可用音源`（error 色） |
| 被其他应用暂停 | `已被其他应用暂停` |
| 无音频输出 | `没有可用的音频输出 · 点按重试` |
| 队列播完 | `队列已播完` |

三个判断值得记住：

1. **换源进行中不算错误。** 一开始它和"确实播不了"共用 error 色和可点的播放三角，等于同时告诉用户"系统在自动处理"和"该你动手了"。现在查找期间用中性灰、主按钮换成圆弧；只有真正查不到才转 error。
2. **平台名在这里用全称。** `displayName` 是"网易云 / QQ音乐 / 酷狗"，混在一起像两种不同的东西。第三行改用"网易云音乐 / QQ音乐 / 酷狗音乐"。
3. **缓冲与换源都不出文字。** 主按钮里是静止圆弧（不是 spinner——无限动画会挂死截图测试）。

## 背景取色：按色度，且以封面自身为参照

**这是这一页最重要的一条，也是返工过两次的地方。**

第一版把 HSL 饱和度钳到很小的绝对值，背景看起来仍是中性灰——因为在 L=0.94 时 HSL 饱和度 0.08 对应的实际色度只有 **0.0096**，和灰没有区别。**饱和度数值在高/低明度下会骗人。**

现在的做法：先量封面自身的色度（`Cover.kt` 种子渐变，实测约 **0.22**）→ 背景色度取它的 **22%**、强调色取 **85%**（刻意低于封面，否则按钮比封面更响）→ 再换算回该明度能表达的饱和度：`s = chroma / (1 - |2L - 1|)`。

| | 背景 | 强调色 | 对比度 |
| --- | --- | --- | --- |
| 浅色 | `#F7E9EF`（色度 0.055） | `#855168`（0.204） | 5.29:1 |
| 深色 | `#2C1E25`（色度 0.055） | `#C38EA6`（0.208） | 5.87:1 |

**主题强调色在这一页完全不用**：每首歌打开都是一间不同颜色的房间，雾蓝/松石青/暖琥珀只出现在其他页面和取不到色时的兜底。进度条未播放轨道也改用 `accent` 22% 透明度，否则中性灰在染色背景上像上一版残留。

**文字仍然不从封面派生**，一律主题 `onSurface`：极端封面上派生文字必然翻车。禁止 blur。

## 一次回溯美学审计（claude-opus-5-5）

F2 收尾时请它回头审了**全部已有前端产物**。结论不好听但有价值：

> 「视觉上还没长出自己的样子。现在的"安静"是靠把东西做灰、做少得来的，没有靠形式本身立住。」
> 「最该是主角的封面，在曲库里只是 96px 的小方块；在全屏播放页里，它的颜色也没能接管画面。」

判定 `generic`：唯一有辨识度的是**文案**（"长 33 秒""在酷狗里确认后返回"——"目录式的诚实"），视觉仍是 M3 默认组件拼装。

它列的 11 条设计语言矛盾里，尚未修的包括：列表行有四种画法、平台标识有四种画法、账号页同时两个实心强调按钮、**曲库为空完全空白**。

三条优先方向：①播放页真取色（**已完成**）②统一表面与列表行（未做）③曲库改封面网格 + 目录式版式 + 补空状态（未做）。

> 教训：此前 `theme_*.png` 画的是封面卡片网格，真实曲库页却是纯文字行——**没人在审真实页面**。已把 `LibraryContent` 从壳里拆出来、加了 48dp 封面和四张真实样张（`library_*.png`）。
## 背景取色

由封面种子色的色相推导，两停渐变：

| | 顶部 | 底部 |
| --- | --- | --- |
| 深色 | L 0.15，S 0.09 | L 0.10，S 0.08 |
| 浅色 | L 0.94，S 0.08 | L 0.97，S 0.05 |

**文字一律用主题 `onSurface`，不从封面派生。** 派生色在极端封面上必然翻车，而"安静的容器"本来就不该让文字跟着封面情绪走。禁止 blur——没有真实封面时，模糊一个双色渐变只会得到一团脏色。

深色 L 起始值是 0.18，复审指出在暖色种子下读起来发棕、发浑，降到 0.15。

## 复审记录（`penguinapi2 / claude-opus-5-5`，三轮）

**第一轮**（判 needs-work，4 个 major）：

| 问题 | 处理 |
| --- | --- |
| 进度到传输行空了约 95dp，下半屏像缺一块 | 把传输行从"固定底部"移进同一个弹性容器，上方 : 下方 = 2 : 1 |

| 已播完但进度停在 1:58 | 样张数据改为 position = duration |
| 平台命名不统一、`由 网易云` 多空格、`已播完 · 队列结束` 重复、缓冲圆弧太细、深色发浑、轨道对比低 | 逐条修掉 |

**第二轮**：9 条确认修好，但**第 1 条判 no —— 因为我上一轮只改了注释、没改代码**。这是这轮最该记的教训：宣布修好之前先量一遍，别只看 diff 里有改动就以为生效了。

## 换源面板

底部弹层（顶部圆角 28dp + 32% 黑色 scrim），背后仍看得见播放页——换源是对当前播放的一次插话，不是一次跳转。实现：`ui/player/SourcePanelUi.kt`（`sourcePanelUiOf` 纯映射）、`ui/player/SourcePanel.kt`（面板）、`ui/design/SourcePanelSheet.kt`（样张，连 scrim 一起渲染）。

外形：候选行 72dp / 圆角 16dp / 48dp 封面；搜索态是**结构化骨架**（封面方块 + 两条文字条 + 行尾短条），不是三块灰砖。

### 倒计时：整行填充

5 秒自动选中第一个同名候选。做法是把即将被选中的那一行**整行背景从左往右填满**，而不是另起一个圆环：

- 行内有一层可见的未填充轨道底（`onSurface` 8%）——4% 时和面板底色分不开，等于没有轨道。
- 填充前沿有一条 2dp 竖边示意方向，透明度 45%——85% 时会从文字上切过去。
- 秒数写在副标题**行首**且带单位：`3 秒后播放 · 酷狗 · 叶惠美`。**绝不能只写一个裸数字**：一排时长里出现「3」，会被读成序号或数量。

### 候选行：时长永不缺席

| 位置 | 内容 | 可否截断 |
| --- | --- | --- |
| 左 | 48dp 封面 | — |
| 中上 | 歌名 | 是 |
| 中下 | `[N 秒后播放 ·] 平台 · 专辑` | 只有专辑可以截断 |
| 右 | 时长（等宽数字） | 否 |
| 右下 | `长 33 秒`（与原曲差 >5 秒才出现） | 否 |

三条硬规矩，都是复审逼出来的：

1. **倒计时不能顶掉时长。** 第一版把倒计时塞在时长位置，等于在最需要判断录音的 5 秒里把时长拿走了。
2. **时长差不能放在会截断的副标题末尾。** 它被省略号吃掉过一次，而它恰恰是区分 live / 翻唱 / 伴奏最可靠的线索（比专辑名可靠）。
3. **面板副标题必须带原曲时长。** 候选写着 4:31、5:02，但用户不知道原曲是 4:29 还是 4:31，就没法比较。

### 失败态

标题就是结论：`没找到能播的《晴天》`，下面只有一句说明，**不重复**。说明点名平台而不是数数——"已在三个平台都查过了"会被读成"另外三个"，把原平台也算进去了。

「播下一首」是唯一强调色按钮；「重试」与「关闭」都是中性色。候选态底部的「跳过这首 / 取消」也全部中性——那个状态真正的主操作是点候选行。

**背景页必须同步。** 失败态时播放页第三行是「暂无可用音源」，不能还写着「正在换源」，否则同一屏出现两个互相矛盾的状态。

### 复审记录（双视角，`claude-opus-5-5` + `claude-opus-4.6`）

**第一轮**：两位都判 needs-work，且都独立命中同一个 blocker——**倒计时数字「3」没有单位**，外加"倒计时吃掉了时长"。另外共同指出时长差被截断、骨架像空态。

**第二轮**：opus-4.6 判 `pass`（只剩 minor）；opus-5-5 判 needs-work，抓到**失败态标题与正文仍在重复**（面板标题「没找到能播的」+ 正文「没找到能播的《晴天》」）。这条对——我只改了一处文案，没意识到标题和正文是两个组件各写一遍。已改为标题独占结论、正文只剩说明。

> 两个模型分歧时，按更严格的那条修。这里 opus-5-5 是对的，而且它给的理由（两个组件各写一遍）说明这是结构问题不是文案问题。
