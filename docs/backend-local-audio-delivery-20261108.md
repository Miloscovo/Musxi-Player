# 本地音频：数据与导入阶段交付

日期：2026-11-08。用户将本地音乐范围扩大为音声/有声书/录音等常用音频，确认副本和授权引用两种选项，倾向复制，并要求“小而精”。本文只记录这一阶段，不将数据层接口等同于播放和正式页面已完成。

## 实现范围

- `core.localaudio`：独立领域模型、自然数字排序、稳定 ID、后端文件能力与公开状态分层。
- `LocalAudioFiles`：64 KiB 流式复制及同次 SHA-256、空间/字节限制、同步落盘和原子发布、取消清半成品、相同内容复用、副本丢失处理、初始化时只清理自身孤儿文件。原文件不删除、不转码。
- `SqliteLocalAudioStore`：Android 内置 SQLite，事务保存音频、应用文件夹、成员顺序、用户别名、每音频进度、文件夹游标、时间书签、revision；引用源已知大小变更拒绝盲目刷新；损坏库报错保留原文件，不静默重建。
- `AndroidLocalAudioDocuments`：系统选文件/目录、持久只读权限、元数据回退、有界目录扫描和显式子目录选项；只释放本模块取得且不再引用的授权，不清其他功能授权。
- `AppLocalAudioRepository`：`MusxiApplication.localAudio` 延迟装配；主线程 callback/StateFlow、IO 串行、逐文件结果、导入取消、重新关联、副本/授权回收、后端播放来源解析。默认 COPY，REFERENCE 可选。

没有新增 Gradle 依赖、Android 权限、原生库或业务服务器，没有变更三平台账号/队列白名单。使用现有协程和系统数据库/文档 API；音频索引与副本位于持久私有存储，不并入普通缓存清理。复制模式删除源文件后的可读性由联合自动化验证；手机听音尚待实机。

测试覆盖文件副本的流式/去重/取消/失效、SQLite 冷读与事务关系、用户别名/进度/书签保留、引用重新关联、两文件夹共享、25 小时位置、原文件删除后副本仍可读，以及 Android 文档目录/权限/排序适配。联合测试使用测试文档提供方/字节源，不是实际系统文件选择器或 Media3 听音结果。

## 后续与边界

1. 下一阶段接同一个 `MusxiPlaybackService`：独立本地队列和 opaque 本地票据、本地/平台来源校验、停止/焦点/定时一致、检查点驱动进度、通知元数据与控制端公开状态。当前网络服务有多处账号代次和 24 小时上限，不能给本地造一个假平台账号直接绕过。
2. 正式前端待 CC：本地入口、文件夹、导入选项/进度、整理和书签。接口见 [合同](frontend-backend-contract-local-audio.md)。现有产品页面未新增入口，视觉未验收。
3. 目录目前是一次性批量导入/重新导入，未保存持续目录订阅、未实时监听或全盘扫描；扫描失效不做删除。
4. 尚无音频导出/数据备份、封面提取、内嵌章节、倍速/AB 循环产品入口。私有副本随卸载删除，导入选项需清楚说明。
5. 同大小外部内容替换不能仅凭文件引用与尺寸可靠识别；格式与实际 seek、长后台、系统回收和通知/定时联动需要后续本包真实设备验证。
