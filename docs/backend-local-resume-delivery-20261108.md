# 本地音频：队列持久化与暂停恢复

日期：2026-11-08。用户确认手机暂时不能接入，继续处理不依赖设备的本地音频后端。本轮补最后本地队列的持久化和恢复；正式界面仍待 CC 接线，设备格式、听音、焦点和后台不计为已验收。前一轮播放服务的 1926 项结果属于当时源码，本轮证据独立记录。

## 本轮行为

- 本地队列保存稳定音频 ID、来源版本、当前条目、位置、临时编辑顺序、循环模式、随机开关与实际随机排列、继续播放偏好。不保存文件路径、文档 URI、媒体票据、平台账号或音频地址。
- 启动播放服务时，若最后活动来源是本地且没有更新用户意图，读取数据库中的最新名称和位置、重建新票据，安装为暂停且未 prepare 的队列；不读取实际文档、不请求音频焦点、不自动播放。三种定时停止不随重启恢复。
- `localAudioPlayback.restoreLastQueue(callback)` 可显式恢复最后本地队列，安装后同样暂停。切换线上音乐或普通 STOP 会使本地日志不再自动恢复，保留显式恢复的可能；清空本地队列则清日志。清空线上队列不删除最后本地列表。
- 数据库每条音频进度继续保存；完整队列文件只在成员/顺序/当前条目/模式/恢复策略变化时重写，周期位置变化只写现有 SQLite 进度，避免长队列每 15 秒重写数 MiB。保存 callback 等进度和队列日志都完成后返回。
- 只安装未播放的队列不会把原进度或完成标记写掉。“从头播放”安装后尚未播放时，恢复仍从零；已经播放的队列按数据库最新位置恢复，支持超过 24 小时。自然结束仍恢复零位置，允许重听。
- 已从库中删除的条目从恢复列表移除，不按文件夹当前成员重新扩建；当前条目被删除时选剩余顺序中其后第一条，否则最后一条。文件夹已删除但音频仍在时降为独立队列；来源重关联造成版本变化则拒绝旧队列，要求重新选择，保留用户名称、进度和书签。
- App 请求序号、服务队列 epoch/recovery epoch、销毁状态与空 timeline 共同拒绝迟到恢复；准备完成的 payload 在服务实际应用时再核验一次。线上歌单开始加载时即让旧本地请求失效，本地主动播放/显式恢复时即取消旧平台加载，避免仍在等网络或 mailbox 的旧操作反向取消新意图。

## 存储与接口

日志使用独立私有目录 `files/local-audio-playback-v1`，版本 1、长度和 CRC32 校验、4 MiB payload 上限，流式有界读取，临时文件 flush/fsync 后原子替换。缺失或损坏日志返回无可恢复队列，不重建或删除本地库。实际读写错误返回脱敏的 `STORAGE_FAILED`。日志不属于普通缓存；平台退出不清理它。

入口、恢复状态和错误语义见 [本地音频合同](frontend-backend-contract-local-audio.md)。恢复状态只公开 `ready/available/restoring/error`；`available` 表示存在保存列表，不保证每个来源仍能读取。正常 `play` 与队列命令仍沿用上一轮入口。
