# 本地音频：同一播放服务接续

日期：2026-11-08。用户授权继续后端，手机稍后可能接入。基于上一阶段数据与导入，接通本地音频的服务入口、文件夹续播和检查点；保持“小而精”、零新增运行时依赖。导入阶段的 1892 项结果只属于当时源码，本轮验证独立记录。

## 本轮实现

- `LocalAudioPlaybackQueue / LocalAudioQueueEntry / LocalAudioPlaybackHost`：本地独立身份，不建立假 LOCAL 平台账号；元数据与后端来源版本分层，队列载荷仍放进程内 mailbox，Binder 只携带命令序号。
- `LocalQueueSources`：每槽位随机 `musxi-local` 票据；loader 才拿到真实受管 file/授权 content URI。替换/删除撤销票据，外部 IO 后再次校验槽位身份，拒绝迟到结果；无真实 URI 缓存。
- `MusxiPlaybackService`：同一个 ExoPlayer/MediaSession/通知/音频焦点/耳机控制/输出与定时停止。网络解析保持旧白名单，本地分流到系统 DataSource；账号变更不清本地队列，读取失败只暂停、不联网换源或静默跳条。
- 本地独立队列状态与 revision 跳转/移动/移除/清空；平台队列和本地队列互斥，切换前保存原来源进度；明确从头 seek 不被历史续播覆盖。
- 暂停、导航、焦点变化、定时停止、自然曲末和 15 秒播放检查点保存本地位置；自然结束及曲末定时暂停保存完成标记/零位置，下一次可从头重听。本地位置沿用 366 天 Long 边界，不影响旧平台 24 小时校验。
- `AppLocalAudioPlaybackAdapter`：主线程入口，先等待服务当前检查点完成，再准备文件夹/单条队列；最新请求胜出；应用级顺序写入进度，服务销毁不取消已交给应用的保存。
- `AppLocalAudioRepository.preparePlayback`：每条音频进度 + 每文件夹游标、未听过/已完成/fromStart/继续偏好；来源版本校验不因改显示名或保存进度失效。读取真实文档前后均核验版本，旧失败不把重关联后的新文件标为损坏。
- 大文件复制/目录读取移出长数据库锁，短保存和文件读取可并行；活跃授权在回收时保留，受管副本读取不等整段复制完成。文件层启动清理仍只在初始化发生。

应用与 CC 入口、参数及状态见 [现行合同](frontend-backend-contract-local-audio.md)。不改正式产品 UI；本地来源禁用平台专属操作由前端接线，现有 UI 未验收。

## 本轮验证

最终索引 `.local/artifacts/local-playback-20261108/final-summary.json` 记录：本轮统一验证目录、测试/Lint、两个 APK 散列、相对上一阶段 debug 包体增量及设备检查。以 [统一工作流](validation-workflow.md) 的实际 `summary.json` 为准，不引用旧报告冒充新结果。

新增验证重点：真实 ExoPlayer/MediaSession 的本地 timeline、无账号建队列、25 小时位置、跨来源保存、每条续播、revision、队列移除/移动、账号退出隔离、定时曲末完成、显式从头 seek；票据撤销与迟到 loader；文件夹/单条准备、重关联版本、完成后重听、保存后再准备、最新请求和导入期间读取/保存。服务单测不宣称实际媒体解码、扬声器听音、通知系统操作或长后台通过。

首轮遇构建产物临时占用：子代理违反禁止构建的任务边界直接启动 Gradle，主线程停止该代理的后续动作，重新使用共享锁入口完成构建；不使用其自行运行的结果作为最终依据。原始 `build-first.log` 保留该轮失败，后续结果独立核对。
