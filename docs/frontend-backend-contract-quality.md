## 改造前的实现

三平台取流都固定为标准档：

| 平台 | 位置 | 当前请求 |
| --- | --- | --- |
| 酷狗 | `KugouLibraryApi.audio` | `quality=128`；`parseAudio` 拒绝非 128k 与 flac |
| 网易云 | `NeteaseLibraryApi`（约第135行） | `level=standard` |
| QQ | `QqLibraryApi`（约第401行） | `M500…mp3` |

PC 端（`frontend/src/components/PlayerActions.tsx`）按当前歌曲实时取得可用音质，选项只来自平台返回，不写死档位；本地歌曲固定“原始音质”。安卓沿用这一原则。

## 需要的能力

1. **查询当前歌曲可用音质**：`qualities(mediaKey) -> QualityOptions`，异步，账号代次/队列身份不符时失败。
   - `QualityOptions(options: List<QualityOption>, current: String)`；`QualityOption(id: String, name: String)`，`name` 为面向用户的中文（如“标准音质”“高品音质”“无损音质”），由后端按平台返回映射，前端原样显示。
   - 平台确认不可用的档位不得出现；无法确认时返回空列表，不猜测。
2. **偏好档位**：`setQuality(id)`，作用于后续取流。
   - 当前歌曲：用新档位重新取流并从当前位置续播；失败时保持原档位继续播放，并返回失败类别。
   - 偏好按平台持久化；歌曲不支持该档位时自动降级到不高于偏好的最高可用档，`current` 反映实际档位。
3. **状态**：`PlaybackState` 增加 `qualityName: String?`（实际正在播放的档位名），供播放页第三行或按钮说明使用。

## 约束

- 不改变既有 ticket、账号代次、换源与有限重试规则；音质切换不得重建队列或改变原队列身份。
- 换源到其他平台时，按该平台的偏好重新确定档位，不跨平台套用档位 id。
- 试听片段、付费/VIP 档位依旧按现有权限规则处理：拿不到完整音频就不列出。
- 新增依赖、签名或接口变更遵守 THIRD_PARTY_NOTICES 与许可要求。

## 前端接入

音质按钮打开底部面板：标题“音质选择”，列出 `options`，当前档位打勾；加载中显示“正在获取可用音质…”，空列表显示“暂无可确认的可用音质”。选择后关闭面板，失败以 Toast 提示且恢复原档位。旧查询结果按当前队列槽位和实际来源校验。
