# 2026-10-27 换源提速与真机验收

QQ、网易云原源无权限的同批歌单样本，此前约 13–15 秒进入播放，本轮首次搜索分别为 **1899ms、2161ms**；同进程再次播放为 **1148ms、1710ms**。两组最终实际来源都是酷狗。计时终点是播放器 `playing=true`，用户本轮不方便听音，不将状态证据记作听感确认。

## 实现

- 严格满足 B4 标题、完整歌手、时长和版本规则的候选收到后立即选择，取消原有 5 秒等待。资格不足的候选继续手选；没有放宽匹配或把网络错误当作权限拒绝。
- 换源专用 SEARCH/SONG 请求使用独立的 2 线程执行器，不再排在整表曲库读取之后。普通读写和音频通道沿用现有顺序，收藏写入不能走搜索通道；session、账号代次及交付栅栏保留。
- 并行搜索有结果可用时提前返回。保留网易云、QQ、酷狗的相对优先顺序；较低优先平台先给出严格合格项时，最多给仍未返回的优先平台 250ms。没有严格合格项时继续等待其余结果，保留不确定版本供手选；单平台 12 秒、整体 20 秒预算保留。
- 只在替代来源真正进入播放后记住原曲到候选的元数据映射：进程内最多 64 条、15 分钟，不存签名音频 URL，不写磁盘。命中仍重新验证匹配和双方账号代次，照常取流。过期、代次变化、元数据不符、该来源失败或本轮已尝试时不复用。
- 原队列身份、最多 3 个替代来源、暂停/停止/跳歌/替换的取消规则保留。已返回候选耗尽后，重新搜索时排除本轮已尝试来源，避免提前返回同一个失败项。自动选择完成后隐藏换源面板；不确定版本继续手选。

代码入口：`AlternativeSourceFinder`、`CrossPlatformSourceSearch`、`RequestLanes`、`SourceSelection`，以及播放服务的候选重试与成功播放回调。没有新增依赖或权限。

## 真机结果

设备 PJF110，Android 16 / API 36。debug 固定验收入口由 DUMP 权限保护，走正式队列与播放服务、真实平台请求。使用原有 QQ 7 首、网易云 5 首歌单的末首，与此前晚间验收选择一致。

| 场景 | 此前成功样本 | 本轮首次无成功映射 | 本轮再次播放 | 首次搜索 / 映射命中查询 |
| --- | ---: | ---: | ---: | ---: |
| QQ → 酷狗 | 13281ms | 1899ms | 1148ms | 536ms / 0ms |
| 网易云 → 酷狗 | 14659ms | 2161ms | 1710ms | 538ms / 1ms |

“首次”指没有该原曲的成功映射；账号恢复和曲库准备已完成，不是应用冷启动。每格一个真实样本，网络状态与此前不同，不作为全曲库统计或一秒内开播承诺。本轮换包前的 QQ 对照因替代流 NETWORK 未进入播放，报告保留为失败，未用于耗时比较。

日志显示 QQ 首次搜索结束后约 4ms 就提交酷狗候选；网易云首次先提交 QQ，明确 PERMISSION 后立即尝试已返回的酷狗候选并成功。两次重复播放均记录 `cache=true`，直接使用成功映射候选，没有重做跨平台搜索，仍重新获取音频能力。

四次播放的队列顺序与整表读取一致，原队列槽位、ticket 和播放器数量校验均通过。搜索中主动暂停后观察 5 秒、搜索中停止后观察 15 秒，分别确认未恢复播放；停止后的队列保持为空。取消测试发生在首次成功映射建立前，使用真实搜索，没有故障注入。
