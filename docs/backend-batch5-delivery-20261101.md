## 三平台头像

- 酷狗：身份验证响应 `data.pic`。
- QQ：优先使用已认证 `GetLoginUserInfo` 返回的 `info.logo / info.nick`，若返回音乐身份字段还需匹配当前会话；资料不全时保留原有的 `GetHomepageHeader / Info.BaseInfo` 备选。真实设备上备用资料接口失败，优先读取身份接口避免头像因此丢失，也减少一次额外资料请求。
- 网易：已验证资料中的 `profile.avatarUrl`。

三平台 Session 带可空 `avatarUrl`，写入既有的本机加密文件；兼容无头像的旧记录，空值、错误类型、超长或控制字符不会使有效账号失效。可选资料缺失时保留先前头像。冷启动先从加密文件发布保存的资料，再验证网络；验证成功后重新保存最新资料。

`AvatarPolicy.sanitize(platform, value)` 独立于 `ArtworkPolicy`，只接受所属平台的图片主机，升级为 HTTPS，拒绝凭据、端口、片段、路径穿越和未知参数。已按真机返回地址校验酷狗图片主机、QQ `thirdqq.qlogo.cn/g`（含 `b/k/kti/s/t`）和网易图片主机；酷狗取 165px、QQ 140px、网易 200px。酷狗尺寸替换采用 Android 兼容的正则，并支持平台的 `{size}` 模板。没有放宽音乐封面策略。

新增可选接口：

```kotlin
accounts.refreshProfile(platform) { result: Result<Unit> -> /* 主线程回调 */ }
```

仅在账号已连接时刷新资料；保存前再次校验账号 ID、阶段和代次。昵称、头像更新不改变代次、会员状态、曲库缓存归属或当前队列。失败通过回调返回，旧资料保留。`AccountProfile.toString()` 保持脱敏；头像地址不加入日志、DUMP 或诊断导出。设备验收报告只记图片主机、尺寸和布尔检查，不包含头像路径或查询参数值。

## 酷狗空歌单保护

确认了两个可把旧页面变成空页面的入口：协议层把无明确总数的 `info:null` 当成空列表；页面层会把成功空结果立即写入磁盘。它们能解释该现象，但当时没有原始响应，不能断言哪一个就是 17:59 的实际触发原因。

现有请求失败本来就保留旧列表。本批另作以下处理：

1. 首页 `info:null` 且没有明确零总数，返回 `incomplete`；明确空数组或零总数仍可表达空列表。后续分页的空结束标记保持兼容。
2. 酷狗首页已有可见或磁盘非空列表时，首次成功空响应保留旧页面和原获取时间，不覆盖磁盘；`stale=true / error="incomplete" / refreshing=false`，可立即重试。
3. 60 秒内手动 `refresh()` 或 `retry()` 再次收到空结果，才允许接受空列表。普通打开及自动失效刷新不能确认；网络失败、非空结果、账号代次变化、缓存清理和失效会重置确认状态。
4. 没有旧非空列表的新账号、其他平台、酷狗后续页与歌单歌曲页不受首页保护影响。

这样能保留短暂异常之前的曲库，也允许用户确实删空歌单后通过手动重试确认。前端已有 `stale / incomplete / retry` 状态，无需新增界面字段。
