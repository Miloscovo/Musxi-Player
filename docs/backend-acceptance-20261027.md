## 音质

QQ 原源歌曲确认标准、高品和无损三档，网易云原源歌曲确认标准、较高和极高三档。最终包标准到 QQ 无损耗时 1303ms、位置 21537→22380ms；网易云标准到极高耗时 601ms、位置 20514→21031ms。两次均确认随后 `playing=true`、`playWhenReady=true`，保留歌曲来源、队列 epoch/顺序和槽位 ticket，偏好写入正确平台。非法档位返回失败并保持当前档位；暂停后切回标准保持暂停及位置。原始结果见 `final-qq-quality.json` 与 `final-netease-quality.json`。

正式音质按钮也完成 QQ 标准到无损的操作，页面显示“QQ音乐 · 无损音质”，随后状态 `playing=true`、`playWhenReady=true`。这证明播放器状态和页面联动，不能替代用户听音。酷狗抽查前 6 首只确认到标准档，未把未确认的高品/无损列入选择，也未将其升档记为通过。

一次网易云报告因为比较整个 `SongSummary` 而失败：重新取流刷新了专辑等元数据，歌曲 key、顺序、epoch 和 ticket 均保持。验收脚本现分别比较队列身份与元数据，保留 `netease-metadata-comparison-before-fix.json` 供复查。首次紧接覆盖安装的探针也因账号仍在恢复而失败；准备步骤已等待账号与播放记录就绪，不把该前置状态当成功。

播放中取流/解码失败的事务回滚、下一首不可用时降档及旧来源异步结果，已有 JVM 测试；本轮未把模拟故障当成真实平台故障验证。未完成酷狗 FLAC 播完再重播。

## 输出

真实系统确认当前为 `SPEAKER`，`inferred=false`。选择当前扬声器成功，无效 ID 返回 `NOT_FOUND`，路由及播放意图保持；播放时和暂停时分别检查。正式“系统媒体输出”按钮打开本机系统“媒体切换”面板，显示“扬声器 / 已连接”；见 `system-output.png`。

实测发现内置听筒被 AudioManager 当作 sink 返回，并误列为名为 PJF110 的媒体候选。现排除 `TYPE_BUILTIN_EARPIECE` 与 `TYPE_TELEPHONY`，保留有效媒体输出；补充针对性单测。最终包外放列表只有手机扬声器，`final-speaker.json` 中 `outputCount=1`，接口检查通过。未新增蓝牙、位置或其他危险权限。

硬件转移、设备名降级、变化在一秒内发布及 NOISY 暂停仍需有线/蓝牙/USB/投屏设备另测；Android 14 及以下版本路径没有实机样本。
