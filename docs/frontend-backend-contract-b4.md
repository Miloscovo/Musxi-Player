# B4：保守自动换源匹配（2026-10-22）

本增量取代首版“5秒后尝试首个同名候选”的自动规则。候选搜索范围、平台顺序、每平台最多10项/总共20项、原队列身份、手动选择及最多3个替代来源均保留。元数据匹配不证明同一录音，也不保证取流权限。

## 自动资格

`SourceSelection.offer()` 对稳定候选列表使用 `SourceMatchPolicy.assess(original, candidate.song)`，按既有顺序找到首个 `ELIGIBLE`，才设置 `automaticIndex` 和 `deadlineElapsedMs=now+5000`。规则同时满足：

1. 标题按既有 Unicode NFKC、大小写及空白归一后相同，保留标点与版本后缀，不模糊匹配。
2. 两侧歌手列表均非空、无空名字或已知“未知歌手/群星”等占位值；规范化后的完整歌手集合相同，忽略顺序/重复项。不会猜艺名别称，也不会按 `&`、`/` 等标点拆分歌手名。
3. 两侧时长均大于0，差值不超过 **3000ms**，也不超过**较短曲目的2%**，边界可取等号。
4. 任一标题/专辑含已识别的现场、翻唱、伴奏、纯音乐、混音、重录、声学、TV Size、DJ、Piano Version、加减速等版本标记，都要求手选；即使两侧都写同一版本标记，也不自动。

版本识别使用有界词表及英文词边界，未接入外部模型或音乐指纹；未标出的版本差异仍可能无法识别。不同专辑名称本身不直接否决自动资格，避免把同录音的普通收录专辑差异当冲突。返回原曲的 key 必须与当前搜索一致；仓库可以为同一 key 补齐缺失元数据，不能用别的 key 替换当前搜索。

## 手选与页面

`SourceSelectionState` 的结构不变：`automaticIndex/deadlineElapsedMs` 由后端计算，前端不能再用 `sameTitle()` 自行决定倒计时。没有合格项时，仍为 `CHOOSING` 且自动索引/截止时间均为null，提供手选/取消；不因5秒过去而自行选择。不得把“无自动资格”显示为“不可播放”。

自动资格不足的候选仍留在既有最多20项列表，可显式手选；不因新的资格规则重新排序或删除它们。手选后仍按既有权限、账号代次、来源尝试上限校验；自动规则不绕过取流检查。用户选择、取消、暂停、停止、队列替换会继续使旧计时/回调失效。

纯函数分类 `SourceMatchReason` 可用于后续解释或诊断：

| 值 | 含义 |
| --- | --- |
| `ELIGIBLE` | 满足本轮自动资格，非录音/权限保证 |
| `TITLE_MISMATCH` | 标题不满足既有精确归一匹配 |
| `VERSION_REQUIRES_CONFIRMATION` | 已识别版本标记，要求手选 |
| `ARTIST_UNKNOWN` / `ARTIST_MISMATCH` | 歌手资料不足 / 完整集合不同 |
| `DURATION_UNKNOWN` / `DURATION_MISMATCH` | 时长缺失 / 超出阈值 |

若同时不满足多个条件，分类按标题、版本、歌手、时长顺序返回第一个原因；不是完整差异列表。前端当前无需额外保存匹配状态或自行调用此函数重做决策。

## 验证与后续

新增12项核心测试覆盖规则边界、元数据不足、完整合作歌手、版本、手选保留、首个合格项、原曲key绑定与同key元数据补齐。当前隔离构建384项测试通过、Lint 0 errors/12 warnings。实际搜索及系统专项的包/设备/限制见 [B4及系统验收](backend-b4-system-acceptance-20261022.md)。

首版历史听音确认不自动迁移为本次匹配结果的确认。保守门槛可能增加手选频率；下一步再根据明确同录音的实际样本调整阈值或别名策略，不以减少手选为由回退成同名自动选择。
