## B1：播放控制器连接恢复

`app.playback.state` 的 `PlaybackState` 追加默认字段，已有订阅保持兼容：

| 字段/API | 语义 |
| --- | --- |
| `connectionPhase` | `CONNECTING`、`CONNECTED`、`RETRY_WAIT`、`FAILED`、`CLOSED` |
| `connectionAttempt` | 当前自动尝试次数；单轮最多 3 次 |
| `canRetryConnection` | 自动预算耗尽后为 true |
| `app.playback.retryConnection()` | 主线程显式重试，重开一次有限预算；连接中/已连接时无操作 |

每次连接最多等待 10 秒；失败后分别等待 1 秒、3 秒再试。短时间内反复连接/断开共用预算，连续稳定 30 秒后再次断线才获得新预算。旧尝试的连接、断线、播放器事件及队列命令确认不能覆盖新连接；迟到资源释放。断线时尚未确认的队列命令回调失败一次，避免调用方一直等待；重连不重发这些命令。

重连只读取服务当前状态，**不提交队列、不 prepare、不 play**。服务保留队列时重新订阅实际状态；服务丢失队列时不会从持久快照自动复活。用户仍通过 `playbackJournal` 显式恢复，恢复保持暂停。`queueState` 是服务拥有的原队列快照，断线时可能保留最后一次值；前端应同时以 `connected` 禁用不可用操作。

前端可在 `RETRY_WAIT/CONNECTING` 显示连接进展，在 `FAILED && canRetryConnection` 展示“重试连接”按钮。连接失败不是曲目权限/音源失败，不应因此启动换源。禁止在页面恢复、连接重试或监听成功时补发播放意图。

纯 JVM 测试覆盖首次连接、超时、三次失败、手动重试、旧回调、快速断连、稳定后重连、重复结果、关闭及同步连接器。它们验证状态机，不能替代 Media3/Binder/系统后台行为的真机证据。

## B2：收藏核实成功后的曲库刷新

`FavoritesBrowser` 构造器追加可选 `onVerifiedChange(platform, identity)`。仅在单曲写入后完整重读、确认目标状态且账号仍精确匹配时通知一次；刷新集合、幂等跳过、写失败、未核实及旧账号结果均不通知。通知异常不反转已经核实的收藏状态。

`MusxiApplication` 已将通知接到对应平台 `LibraryBrowser.invalidate(identity)`，不需要页面再触发同一轮刷新。该方法拒绝未验证/过时账号，作废未完成的旧页请求，直接从网络重取当前查询页。同账号保留已显示内容；账号通知尚未收集时也先清掉其他账号的页面。其他平台不变。列表刷新失败不会反转收藏成功，也不会自动重试写操作。

`LibraryBrowseState` 新增：

| 字段 | 前端处理 |
| --- | --- |
| `invalidationRevision: Long` | 进程内单调增长；变化时清空/重建 ViewModel 自行累计的分页，防止旧页与新页拼接 |
| `stale: Boolean` | 页面内容可能早于最近一次收藏变化；可保留显示并提示刷新，不能当已同步成功 |

成功网络页清除当前页的 `stale`；失败保留原内容及过期标志。失效后访问其他缓存页会保守标记过期，直至该页网络成功；未做全库重扫或删除持久元数据。网络成功但磁盘写失败时，当前网络内容仍可用，后续读到旧磁盘页仍标过期。失效标志仅在进程内维护，冷启动仍遵循原缓存优先/联网刷新行为。

追加测试覆盖通知一次、幂等/失败零通知、旧回调拒绝、账号收集延迟、换号清页、其他账号不继承过期标志、失败保留内容和磁盘写失败。已有账号/平台隔离测试继续运行。

## B3：有界、脱敏的逻辑请求计时

通过 `app.accounts.requestTimingSnapshot()` 获取不可变聚合快照，通过 `clearRequestTimings()` 开启新观测窗口。可从任意线程读取/清理，统计只驻留内存，进程结束即丢失。没有后台采样、上传、日志输出或新增生产依赖。

最多 3 平台 × 10 操作桶。固定操作包括歌单、歌曲页、单曲元数据、搜索、队列、取流、收藏读取/写入、歌词和其他。三平台曲库/搜索/取流及收藏/歌词仓库已标注操作；登录验证不纳入这一组会话工作统计。

每桶提供提交数、执行完成数、SUCCESS/FAILED/REJECTED/STALE 完成数，以及 queue/work/delivery 三段累计及最大毫秒数：

- queue：进入共享串行工作队列至工作开始。
- work：工作开始至逻辑操作完成；含账号检查、可能多次 HTTP、解析与组装，**不是单次 HTTP 耗时/请求数**。
- delivery：工作完成至主线程开始接收结果，不含 UI 绘制。

`REJECTED` 表示未进入业务工作即被账号条件拒绝；`STALE` 表示执行后账号变化或明确的失效异常。SUCCESS 是 worker 结果；在 worker 完成与主线程投递之间换号，投递仍按原账号规则拒绝，但已记下的 worker 结果不改写。取消搜索拒绝迟到结果，尚不能用这些桶精确推导取消后 HTTP 剩余工作量。未完成请求没有计入对应阶段，不能直接以提交数作所有阶段均值的分母。

只保存平台/操作枚举、计数和时长，不接收账号标识、搜索词、歌曲 key、凭证、原始响应或音频地址。测试覆盖分段计时、重复回调、clear 隔离、平台隔离、不可变快照、时钟回退/饱和与 30 桶上限。

当前交付是测量基础，尚无真实设备耗时样本，也未做按平台并发、播放插队或缓存目录策略调整。下一步按相同窗口复现搜索/翻页/收藏核实与取流竞争，读出排队比例；若确有瓶颈，再单独设计调度及取消残余测量，保留账号隔离与磁盘清理顺序。
