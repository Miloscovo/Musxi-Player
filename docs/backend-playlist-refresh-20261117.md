# 酷狗下拉刷新后的自动分页循环修复

2026-11-17。用户反馈酷狗曲库下拉刷新后，“加载更多”与“正在读取”持续交替。本轮只修分页读取；保留账号与本地数据，不执行平台写入、不提交推送发布。前一轮接入背景见[歌单前端接入审查](frontend-playlist-review-20261117.md)。

## 根因和修复

`FileLibraryPageStore` 写入新的 offset 0 页时，会清除旧的续页缓存，避免把旧目录尾页拼进新目录。`LibraryBrowser` 同时保存每个查询最近 30 秒的网络成功记录，用于减少重复读取。刷新首页后，这两份状态出现不一致：offset 30 的缓存已被清掉，其近期成功记录仍在。

原实现因此跳过续页网络请求，交付 `content=null, refreshing=false, error=null`。Catalog 保留 `nextOffset=30`，页面的自动分页再次触发；下一次又命中同一条近期成功记录，导致加载状态反复切换。酷狗未知总数的短首页需要额外空页确认完成，因而在少量歌单时也能触发这个问题。登录正常，接口本身也能返回空终页。

现在只有实际读到有效缓存页时，才允许近期成功记录抑制请求。缓存缺失或已失效时正常请求网络，沿用原有账号代次、取消栅栏、平台限速与错误处理。外层 `refresh` 条件保留，`refresh=false` 仍仅读缓存；正常缓存命中仍避免重复请求。没有增加定时重试、强制认定短页为末页，或隐藏加载提示。

## 回归与实机证据

- 核心回归在修复前已失败：同一时钟下先完成短首页／空终页，再立即刷新首页，offset 30 因近期成功记录而不再请求。测试缓存模型现与生产一致：写首页清除尾页。
- 修复后核心目录测试连续刷新三轮，每轮都重新取得空终页并确认 `complete=true`；完成后多次 loadMore 不增加请求。
- Browser 测试覆盖三平台目录缓存丢失后的网络回退、歌曲详情同类情况、缓存恢复后的请求去重，以及缓存缺失时 `refresh=false` 不联网。
- 手机 `PJF110 / Android 16` 上先完成酷狗目录，再连续刷新三轮，四轮最终均为 3 项、`complete=true`、`loading=false`、无错误。测试主动 loadMore 次数均为 0，续页由正式页面的 AutoLoadMore 完成；每轮保持完整状态至少 3 秒。
- 同包三平台目录／非空详情、本地库 ready 与 DSF 能力只读回归通过：酷狗 3／30、QQ 2／7、网易云 3／12（目录数量／所选详情首页曲目数量）；三平台目录均 complete=true。本地原有 1 条、DSF=true。
- 两轮真实下拉手势均观察到“正在读取”后正常消失，每轮后续三个页面快照均无“正在读取”及“加载更多”，歌单行保持可见；观察跨度约 20 秒。手势观察和截图独立留证，不把程序调用刷新冒充手势验收。
