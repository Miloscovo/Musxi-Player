# 酷狗网页登录验证（2026-10-28）

本机的酷狗官方网页可以完成手机号、滑块和短信登录，但取得的网页会话尚不能用于 Musxi 现有音乐接口。身份与歌单请求均被平台拒绝，未接入正式账号页；现有酷狗登录保持原方式。

## 实机结果

设备为 PJF110 / Android 16，本轮测试仅代表当前设备、账号、网络及所用官方页面。

| 步骤 | 本轮结果 |
| --- | --- |
| 打开 `https://login-user.kugou.com/login/?appid=1014` 官方页面 | 成功，默认显示手机扫码 |
| 切换手机号登录 | 入口在登录框右上角的账号小图标，用户反馈初版勉强可见、可点 |
| 手机号、滑块、短信验证码 | 均由用户本人完成，无需在本轮流程中打开酷狗 App 确认 |
| 取得网页会话 | 成功，从本 App WebView 的 `KuGoo` Cookie 解析 `KugooID` 和 `t`；没有读取输入框 |
| 对比现有账号 | 网页 Cookie 中的用户 ID 与原加密会话中的用户 ID 一致，不对外记录 ID |
| 原会话的身份请求 | 通过，作为同设备、同网络下的对照 |
| 网页会话的身份请求 `/v3/get_my_info` | 平台拒绝（`platform`） |
| 网页会话的本人歌单请求 `/v7/get_all_list` | 平台拒绝（`platform`），没有取得歌单数量 |
| 保存为可用音乐会话 | 未执行；身份、曲库双重验证未通过 |

用户最初只能看到二维码；公共脚本中的切换按钮实际会显示手机号与短信表单。实验窗口随后设置初始缩放 140 并保留双指缩放，用户完成了短信流程。这个布局调整仅属于当前 debug 验证窗口，尚未覆盖屏幕尺寸、字体和横竖屏矩阵。

网页登录成功和音乐接口兼容是两项不同的验证结果。用户完成官方验证、发生官方登录后跳转，并且取得会话，可以确认这条网页认证路径本轮可行；Cookie 中的 ID 一致本身不等于音乐服务已确认身份。原会话通过、网页会话两项请求被拒，支持“现有接口尚不接受该网页会话”的结论，不能据此断言所有酷狗接口或账号均不支持网页登录。

## 协议调查的边界

官方首页的 `popuplogin-min.js` 构造登录入口；登录壳加载 `kguser.v2.min.js` 和 `popuplogin.v3.min.js`。后者默认 `appid=1014`，通过右上角 `j_kg_popup_switch` 从扫码切到手机号验证码表单。

现有安卓适配器的身份与曲库请求使用 `appid=3116`。不同 appID 可能影响 token 兼容性，但本轮没有获得能确认原因的服务端证据，不将其写成已确认原因，也没有更改正式签名或伪造会话来源。

公共脚本的 `AutoLogin()` 使用 `/v1/autologin` 恢复浏览器会话，响应按脚本执行，未能从静态源码确认音乐身份 JSON 或曲库权限。没有把 HTTP 200、Cookie 存在或自动登录恢复当成音乐服务验证成功，也未发现可据以实施的网页 `t` 换发安卓音乐会话流程。后续接入需要有来源可核对的会话交换或网页曲库协议，再重新验证身份、本人曲库及重启恢复。

## 实现与数据保护

实验窗口和 Cookie/导航策略位于 `platform-kugou/src/debug`，测试位于 `src/testDebug`；验收 Activity 和固定步骤位于 `app/src/debug`。正式账号页、账号 Repository 和登录流程未新增酷狗网页入口。Activity 不导出，固定广播入口受系统 `DUMP` 权限限制；release 的 DEX 与 Manifest 均已检查，不包含实验类或验收入口。

只允许 HTTPS 酷狗域页面，拒绝伪造域名、异常 authority 和 TLS 错误。没有密码/短信读取、DOM 读取、JS bridge、控制台日志或 Cookie 明文日志。浏览器 Cookie 留在 App 私有目录；没有清除共享浏览器数据，没有将凭证送至电脑。重试直接在手机内复用当前网页 Cookie，没有要求用户再次收短信。

原 `no_backup/kugou-session.enc` 在验证前、重新连接手机后、重试后和最终安装后摘要一致，最终原会话身份对照也通过。未退出、换号、清数据、写收藏或修改队列。最终新快照为三平台 `CONNECTED`、暂停、队列 0；没有恢复历史队列或自动启动播放。
