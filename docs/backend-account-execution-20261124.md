# 账号后端第二批：平台执行隔离与校验合并

2026-11-24。用户授权推进[账号规划](backend-account-planning-20261124.md)第二批。保留首批明确过期、60 秒恢复冷却和验证事实；前端、持久会话格式、平台协议及公开账号操作接口保持原有接线。

## 执行职责

三平台分别使用单线程账号 worker，负责本平台加载会话、启动／手动恢复验证、登录创建与轮询、资料刷新、保存凭据和退出清理。同一平台仍串行；网易云慢验证不再占用 QQ／酷狗账号执行机会。

普通曲库业务继续使用原串行队列，音频取流和播放搜索保留原旁路；账号不再与普通曲库 HTTP 排队。会员查询也按平台独立串行，与本平台账号 worker 分开，继续保持可选元数据失败不影响登录的规则。缓存写入与擦除仍共用原 `cacheQueue`，保证退出后旧缓存写入不能复活；不把共享磁盘队列描述为完全并行。

全局账号锁只保护状态和小型内存记录。每个平台另有提交锁，将该平台的凭据保存／清除与 generation 变化排序；磁盘提交不再占用其他平台的账号锁。HTTP 不持有这些锁。网易云临时扫码图片的初始化、保存和清理仍全部在网易云账号 worker 上执行。`pending`／轮询任务容器改为可跨平台访问的容器，同一 key 的复合操作仍由其平台 worker 串行负责。

## 合并与有界等待

| 操作 | 当前行为 |
| --- | --- |
| `restore(platform)` | 活跃恢复／登录期间拒绝重复请求；已有同代资料刷新时复用其验证，不再排新恢复 |
| `refreshProfile(platform, callback)` | 同一平台、同一 generation 的重叠调用共用一个 verify；各 callback 在主线程收到一次结果 |
| 资料刷新等待者 | 最多 64 个；超出立即返回既有不可用错误，不新增 HTTP |
| `checkNow(platform)` | 同平台正在执行或已排队的手动轮询合并；后台与定时轮询规则保留 |
| 启动／手动恢复与资料刷新 | 主线程 watchdog 等待 45 秒；恢复超时进入 `RETRYABLE_ERROR / NETWORK`，资料刷新超时保留连接状态并记录 NETWORK |
| 登录尝试 | 自开始起最多 180 秒，超时进入 TIMEOUT；保留官方授权／验证码由使用者完成的边界 |

超时意味着不再接受该次结果，不强制终止底层连接或创建替代 worker。三平台 HTTP 原有连接／读取时限均为 18 秒；多个请求组成的登录操作可能更长。同一平台正在退出时，会先让旧 HTTP 返回，再串行擦除私有数据，擦除成功后才报告 DISCONNECTED；取消则立即淘汰当前代次。磁盘提交一旦开始，和同平台取消排序，不承诺存储故障的强制中断。

资料刷新超时后保留物理请求占用记录直至 worker 返回，期间再次刷新会立即失败，不持续积累等待者。晚到的成功／认证失败都不能保存凭据、覆盖验证事实或第二次交付。退出／取消可立即结束资料刷新等待者；旧 worker 返回后的清理只移除自己的请求记录，不能影响新代次。

首批自动恢复仍仅针对有保存身份的 NETWORK 失败，不为超时创建周期性重试。新前台／已验证网络事件或明确手动重试继续遵守原资格与冷却边界。后续[第三批](backend-account-reauth-web-20261124.md)已补三平台原位重认证、网易云关闭保留／退出清网页会话；退出中的取消不恢复已删凭据。
