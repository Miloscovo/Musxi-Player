# 登录与账号后端讨论

2026-11-24。三轮共同范围均为网易云、QQ 音乐、酷狗。用户安排前端暂缓；[首批状态与恢复](backend-account-status-recovery-20261124.md)、[第二批执行隔离](backend-account-execution-20261124.md)及[第三批原位重认证](backend-account-reauth-web-20261124.md)已按授权实施，第三批另含网易云现有网页登录的会话管理。当前无手机，真实三平台登录与新增前端接线待验。

## 前端保留事项

- 歌单“新建歌单”浮卡与当前 Musxi UI 风格不匹配，沿用此前视觉待办。
- 本地音频删除单曲时，“从本地库删除这一条？”确认浮卡同样需要统一风格。
- 三平台账号列表进入平台页后，再点账号弹出管理浮卡，层级偏多。后续建议在平台页直接展示状态、登录／重新验证操作，退出保留确认；是否保留独立平台页按其实际内容决定。
- 上述三处应用浮卡均使用 Compose Material3 `AlertDialog`，黑色圆角来自组件和当前主题，可统一封装为 Musxi 的材质、圆角、排版、按钮与动效；系统权限／文件选择器仍遵守系统交互。本批不改 UI。
- 锁屏歌词 C 正式前端尚未实现；既有后端、权限边界与接口合同保留，后续集中接线。

本阶段不改这些页面或浮卡。后端每个小批次应同时交付状态语义、错误与动作接口、验证及接线说明，避免仅积累未验收功能。

## MeiloX 本轮参考

主仓库以 [固定提交 `0256aac727a29477c9a1741ef0286925c2700680`](https://github.com/MeiloX/MeiloX/tree/0256aac727a29477c9a1741ef0286925c2700680) 为准；网易云独立音源仓库以 [固定提交 `64be4aaf985f2dd29a8804ede3c081646c0e40fb`](https://github.com/MeiloX/MeiloX-Netease-Source/tree/64be4aaf985f2dd29a8804ede3c081646c0e40fb) 为定位依据。本轮阅读公开 README、`docs/music-sources.md`、`docs/multi-source-architecture.md`、插件合同相关段落及主仓库 `NeteaseAccountSession.kt`。旧本地 `bc038c9` 仅用于理解历史实现，不将其旧登录轮询器视为最新生产路径。未构建参考项目，未复制其代码／SDK／资源或安装其插件。

当前 MeiloX 已将默认网易云做成可移除的独立音源：平台协议和私有会话存储属于音源，已验证账号身份、缓存、刷新策略与认证错误失效由宿主协调。文档明确区分网页登录与移动端登录来源；CSRF 或匿名字段轮转不等于切换账号。账号、页面和异步操作绑定具体音源实例／版本／账号代次，退出后的空会话不会被旧配置重新填回。

网页登录使用音源隔离的 WebView profile，普通关闭保留网页会话，明确退出才清凭据；不能使用独立 profile 时不退回全局 CookieManager。这是可研究的边界，不能直接移植成 Musxi 所有 Android/WebView 版本均支持的承诺。移动密码、短信与二维码需要宿主提供的交互和协议原语，不能从功能清单推断为可直接替换 Musxi 登录。

Musxi 可先借鉴职责与会话边界。当前固定三平台、七模块的规模，暂不建议仅为协议更新引入 QuickJS、插件市场、权限声明和插件升级迁移体系。

## Musxi 已有基础与实际缺口

已有进程级账号协调器、generation 防止迟到结果、加密会话存储、平台资料身份核验、会员状态隔离与请求指标；无需将这些当成缺失重做。

源码确认的优化点与当前状态：

1. 首批已统一 `refreshProfile` 与三平台业务请求的明确 `expired` 处理，按 expected generation 失效账号，保留本地身份与凭据；网络、风控和版权失败不退账号。
2. 第二批已将账号生命周期 I/O 按平台串行隔离，并与曲库业务队列分开；会员查询按平台隔离。同代资料刷新合并、最多 64 个等待者、45 秒等待时限；登录总等待 180 秒。取消、退出和超时通过 generation／请求完成标记拒绝迟到提交；细节与磁盘／底层 HTTP 边界见第二批合同。
3. 首批已为暂时网络验证失败补充前台／已验证网络恢复触发的一次有界验证，平台独立冷却 60 秒；显式 `restore` 与现有重试入口保留，自动失败不自循环。
4. 第三批新增三平台原位重认证接口：候选独立验证、原子存储后替换，同用户保留缓存、换用户按 owner 隔离，失败／取消／超时回滚原状态和凭据。正式前端仍使用旧的先退出流程，后续按第三批合同接线。
5. 第三批区分网易云窗口关闭与明确退出。API 28+ 沿用应用已有 `netease_login` suffix，关闭保留网页会话；26／27 临时会话降级。退出、清理未完成后的重开及进程中断以主线程串行清理和持久待办／revision 保护；QQ／酷狗仍走官方授权，不移植 debug 网页入口。

## 建议的小批次

首批聚焦“状态与恢复”：统一过期处理、明确暂时失败恢复、最小脱敏诊断和相应用例，先修可验证缺口。第二批做平台执行隔离与校验合并，覆盖切号、取消、退出和迟到响应。第三批再做原位重认证及 WebView 会话生命周期。密码／短信等新入口在这些基础稳定后按平台实际支持分别评估；不承诺三平台同样流程或支持无限期续签。

后端可补“上次成功验证时间、最后一次错误类别、是否建议重登”，让后续前端准确表达状态。读取曲库、播放、写歌单是不同请求能力，其结果应按上下文记录；不在每次启动自动取音频测试登录，也不让单曲版权／试听问题将整个账号标为失效。

三批已按用户授权实施；不自动新增密码／短信入口。无手机时以自动化和构建交付，真实账号及浏览器实机另验；三批均不执行真实账号过期、退出／换号或平台写入，不提交、推送或发布。
