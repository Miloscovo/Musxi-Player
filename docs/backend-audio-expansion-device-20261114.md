## CUE：第一、二批实机

通过 `AudioExpansionDeviceTest` 显式 opt-in 阶段调用正式 facade。系统提供方为 `com.android.documentsui`／外部存储文档；在专用 Download 目录选择真实 GB18030 CUE 与已严格校验的好 FLAC。CUE 原名称不符，通过明确的候选 0 → 文件 0 绑定导入，不猜测同名来源。

| 项目 | 观察结果 |
| --- | --- |
| 预览与取消 | 实际解析 24 轨；取消系统文件选择后条目／文件夹不变 |
| COPY | 入库 24 个分曲，底层 location 仅 1 个；重复导入保持同一批 ID |
| 分段播放 | 第 1／12／24 轨实际解码；时长分别约 43,493／112,893／62,466 ms，seek 为段内位置 |
| 轨道边界 | 第一轨曲末定时停在该轨；单曲循环留在该段；自然进入第二轨和上一首回第一轨通过 |
| 书签／恢复 | 段内 2,000 ms 书签保留；进程重启恢复暂停队列、ONE 循环及约 3,500 ms 进度，REFERENCE 可继续解码 |
| 权限 | 仅释放本次音频的持久授权，重启后查询／来源检查返回 PERMISSION_REQUIRED，条目 ID 保留；独立 COPY 仍能播放 |
| 删除共享来源 | 删除一条分曲后其他分曲仍能实际播放，受管共享副本仍被保留 |

早期引用导入被 STALE_STATE 拦截：暂停／循环事件会延后约 200 ms 保存进度，测试过早冻结曲库 revision。改为等待写入稳定、显式 checkpoint 后再取版本；没有放松生产版本检查。该现象也说明前端遇到 STALE_STATE 应读新状态再明确重试。完整拆分整理／进度 revision 仍是既有独立待办，不能简单取消进度的版本递增。

最终包第一次冷恢复检查在队列 ID 先到、MediaController 状态尚未到时读到默认 OFF；随后私有日志仍是 ONE。修正测试观察条件后重新 force-stop 补验，不把这一失败隐藏成首次通过。

不据此宣称物理无缝、正式页面手势、跨系统文件提供方、切平台恢复、长后台／锁屏均已验收。

## 格式：第三批实机

实际播放 FLAC、标准 RIFF PCM WAV 与 MP3，观察来自同一 Media3 服务：

| 样本 | 输入／文件头 | 应用 AudioTrack |
| --- | --- | --- |
| CUE 共享 FLAC | 44,100 Hz／16 bit／双声道 | 首次观察 44,100 Hz；重用已有 sink 而无新初始化事件时值可为 null |
| 合成静音 WAV | 标准 PCM 头，96,000 Hz／24 bit；文件头查询与输入事件一致 | 96,000 Hz |
| 合成静音 MP3 | 48,000 Hz，`c2.android.mp3.decoder`，未猜测压缩源位深 | 48,000 Hz |

停止后活动解码器及应用输出观察清空。`decoded` 与 `deviceOutput` 均保持 null；这些值不能证明系统混音后、蓝牙或外接解码器最终格式。

早期合成 WAV 由 ffmpeg 写成 WAVE_FORMAT_EXTENSIBLE，当前只读查询按合同保留未知；改用标准 PCM 头补验。更换这份测试文件后旧引用正确返回 SOURCE_CHANGED，随后用新的专用文件名测试。没有为了使测试通过而放松来源版本检查或扩展格式承诺。

## DSF：第四批数值与设备评估

真实样本 1,092,855,071 字节，DSD256／11,289,600 Hz／1 bit／双声道，约 386,493 ms。只读预览成功。尾部 ID3v2.3 共 2,008,259 字节，超过既定 1 MiB 标签上限，因此 tagStatus=UNAVAILABLE 是保守结果；不通过扩大读取上限加载其中大图。未宣称真实标签／封面已读出。

转换仍为项目内构造的 257 tap 首级低通与 65 tap 后续级，输出 176.4 kHz float PCM，未新增运行依赖或 native ABI。本轮加入字节查表、完整字节路径及镜像历史缓冲，对称滤波减少重复计算；保留标量尾位与滤波零值补尾。

- 内核／Extractor 14 项及解析／标签／应用预览 39 项，共 53 项第四批新增用例进入统一回归并通过。
- 同一样本前 20 秒，镜像优化输出与前一查表版本逐 float 一致；最早直接 FIR 与字节版本前 2 秒最大绝对差约 `2.75e-11`。
- 与 ffmpeg 的 176.4 kHz float 参考比较，在 10～12 秒片段原始相关约 0.9981；对齐 2 个 PCM 帧后约 0.99989，RMS 约 0.0121945。前 20 秒峰值约 0.08159、无非有限值。这是该片段数值对照，不能当作所有输入的听感、THD 或设备输出验收。
- 对系数做有限频率网格分析，20 Hz～20 kHz 幅频偏差约不超过 0.00026 dB，采样的可闻混叠带上界约 −110.6 dB；这是数值网格，不是全频严格证明或实测硬件信噪比。
- 手机 debug 开关内，成功进入同一服务并观察 176.4 kHz PCM 输入与应用 AudioTrack；60 秒 seek 读回 60,002 ms，曲末读回约 386,501 ms，与声明毫秒时长相差约 8 ms。曲末确实结束，无按整块填充继续播放的长尾；仍未做真人听音判断。

**实时门槛失败：**早期版本启动后很快缓冲；镜像优化后桌面前 20 秒处理时间约由 15.43 秒降至 4.42 秒，但手机仍未达到实时。脱离 instrumentation 的固定 debug 接收器又观察了约 122.37 秒，仅推进 53.86 秒，进程 CPU 约 168.93 秒；停顿时 playWhenReady=true、buffering=true、suppression=NONE。以上记录来自 Musxi 自身进程。PSS 包含页面／服务，不当作解码器独占内存；充电且游戏运行的条件不用于定量耗电结论。

因此不开放正式 DSF 导入／播放，不以增大缓冲掩盖长期吞吐不足。后续优先评估可维护的原生转换内核／优化实现，核对 ABI、许可、包体、取消与长期 CPU，再对同一参考、seek、末尾和持续播放复验。DSD64／128 的回归通过不等于相应真实设备播放已通过；本轮真实音频只有 DSD256。
