# 发布签名、公钥证书与私钥

状态：2026-11-03 核对；配置见 [Release 构建](release-build.md)。本文不包含密钥或密码。

## v0.2 公开材料

正式包名为 `tech.musxi.player`。v0.2 更新清单的 `signerSha256` 为：

```text
7475490939bccd3836755b09e571a6792607f2115dacd345e3aeb2508d2a8eef
```

这是公开签名证书的 SHA-256 指纹。证书本身（含公钥）、证书指纹、APK 哈希和签名值可以公开；APK 中本来就携带验签证书。它们不能用于恢复对应私钥，也不能给任意修改后的 APK 签名。

本轮检查当前追踪文件与可达 Git 历史中的常见私钥库扩展名、文本私钥标记，没有找到正式私钥库或文本私钥提交。结论限于该范围，不等于审计所有外部备份、日志、账号 Secrets 或远端不可达对象。

## 当前配置

`app/build.gradle.kts` 要求正式 keystore 位于仓库外，密码通过进程环境 `MUSXI_RELEASE_STORE_PASSWORD` 输入；缺配置会失败，不回退开发签名。v0.2 发布记录使用所有者管理、长期保存的专用应用发布私钥，开发包 `tech.musxi.player.dev` 签名独立。

当前已经采用个人保管的专用发布私钥。不必为隐藏证书指纹重新生成密钥，也不应复用个人 SSH、GPG 或其他应用私钥。发布密钥独立保存并做受保护的离线备份；本轮没有更换、导出或生成密钥。

## 更新与自动化

Android 覆盖更新要求签名连续性；本项目更新校验也要求新包证书与当前包一致。直接换全新私钥会破坏现有 v0.2 覆盖升级路径。确需轮换时，须先设计 APK 签名轮换 lineage、旧系统兼容和应用内校验迁移，再验证真实双版本覆盖，不能仅换 keystore 路径。

普通 CI 构建开发包，不需要上传正式密钥。未来自动发布可单独采用受保护的发布 environment 与 Secrets，由授权任务临时取得密钥；Base64 只是编码。MeiloX 的 Secrets 签名展示了公开配置与私密值的区别，但 Musxi 无需照搬其每轮签名方式。
