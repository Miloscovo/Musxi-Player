## 本轮实现

- 三平台完整有序歌单 ID 读取和普通歌单移除；写前服务端重验所有权，账号代次贯穿读取、写入和回调。
- 单首歌曲的多个歌单归属快照、明确设置/保留、逐目标结果及失败项重试路径；红心与普通歌单独立，省略的目标不改变。
- 原单歌单添加接入同一套写前读取与写后确认；增加单歌单多曲增删、创建后添加的独立结果。
- QQ、网易云创建普通歌单，返回 ID 后读取确认；网易云普通歌单改名并读回确认。拒绝红心歌单改名。
- 红心沿用 FavoritesBrowser 的同步、顺序和写后核实；从歌单归属入口发起时先同步，避免依赖某个前端页面预先初始化。
- 新增默认不执行写入的专项设备测试：测试歌原本不在目标中，写前持久化当轮恢复意图，添加后验证幂等，再移除并核对全量顺序与红心不变。

接口与状态详见 [歌单管理后端合同](playlist-management-contract.md)。`Result.success` 不等同于每个目标都成功，调用者必须检查 `successful` 与逐项 `status`；写入结果不明时先重新读，不能盲目重试。
