# 在线歌单与点播延迟

打开歌单后的歌曲列表使用当前服务会话中已有的最多 24 项读缓存：命中后立即显示，后台重新读取。首次加载的普通歌单按上游分页或详情批次显示，顺序保持不变。酷狗收藏需要全量排序，因此保留完整读取；跨平台收藏整合按已完成的平台显示，并在结束前标记为加载中。歌曲列表的读缓存不跨账号或服务重启复用。

## 启动时的歌单目录

启动时优先显示本机 `online-playlists.json` 中上次成功同步的歌单卡片。缓存仅保存目录元数据、平台、稳定账号 ID 和同步时间；凭证继续由已有的加密会话存储管理。读取缓存时按加密会话中的账号 ID 匹配；验证前卡片只读，验证和目录读取完成的平台分别开放操作。换号、退出登录会清除相应快照，成功的空目录会覆盖旧目录，网络失败不覆盖成功快照。无账号 ID 的旧快照不会直接复用；升级后首次成功同步建立新缓存。

服务内部 `startup` / `startup_state` 在后台推进三个平台的验证和目录读取。VIP 领取、精确收藏数量、缺失封面、头像与会员信息不再阻塞卡片显示；酷狗首次授权播放仍等待正在进行的 VIP 领取，避免提前误报无权限。后台 QQ 收藏读取沿用分页串行队列，在页间允许前台点播和打开歌单。

`library.getState` 新增可选的 `playlistsRefreshing`、`favoritesCountKnown`，账号条目新增可选的 `verifying`、`playlistsReady`。前端根据这些状态开放各平台卡片，移除原先等全局 busy 结束后再延时 800ms 的骨架屏逻辑。未知收藏数量显示占位符。

运行 `node tests/online-latency.cjs --startup` 可复测固定接口延迟下的启动链路，输出 `build/startup-playlists-results.json`。五次测量中位数：旧服务串行链路 659.9ms（另有已移除的前端固定 800ms 等待），新流程首个平台可操作 58.0ms、全部平台可操作 277.1ms、后台附加工作完成 458.6ms；服务返回缓存首屏约 0.1ms。以上不包含原生文件读取、CEF 启动、界面绘制或公网延迟。

CEF 方法名和参数不变。`library.getState` 新增可选布尔值 `playlistLoading`、`playlistIncomplete`。服务内部使用 `tracks_start` / `tracks_progress` 和 token、revision 识别加载任务，未变化的列表不重复发送。加载中的单曲可以点播，整个歌单的播放按钮需要完整加载成功。失败不会覆盖成功缓存或保存为完整快照；过时响应不能替换新选中的歌单或取消刚点击的歌曲。

前台音频仍通过账号授权的地址下载，FFmpeg 继续只读取本地文件。已知长度、识别出可顺序读取的 MP3、FLAC 或 AAC 时，服务提前返回缓存路径，并用同名 `.download` 文件提供最终长度。解码器在临时文件尾等待新字节，超前拖动进度也会等待所需数据；取消可以中断等待。下载失败通过 `.failed` 标识传给解码器，其他容器或未知长度仍完整下载后播放。每次下载最多 512 MiB、75 秒；解码等待上限 80 秒。

未完成下载不会保存为下次启动可恢复的音频。网络下载失败后点击重试，会重新走现有授权和点播流程。当前歌曲下载完成前不启动下一首预取；手动点击已准备好的下一首复用现有文件。原有音质、权限验证和单首预取范围保留。原生状态轮询从 150ms 缩短为 50ms，前端在歌单更新期间沿用已有的快速轮询。

## 可重复测量

在项目根目录运行 `node tests/online-latency.cjs`，结果写到 `build/online-latency-results.json`。脚本使用真实平台适配器的模拟上游，900 首歌、每次请求固定延迟 25ms；音频为本机 HTTP 的 1MiB 数据，每 25ms 发送 64KiB。每项测量五次，并断言完整列表和下载字节正确。无需账号，不访问平台、不记录私有数据。

一次运行的中位数如下，单位为毫秒。它们衡量服务返回数据或可读取路径的时机，**不包含 CEF 展示、设备启动、实际出声或公网延迟**。

| 场景 | 等待完整结果 | 首批可用 | 缓存首屏 |
| --- | ---: | ---: | ---: |
| 网易云歌单 | 103.7 | 52.3 | 1.8 |
| 酷狗歌单 | 293.1 | 33.0 | 2.1 |
| QQ 歌单 | 225.6 | 25.4 | 0.8 |
| 音频路径 | 410.2 | 29.7 | — |

服务测试验证缓存隔离、取消、失败、分页与 QQ 单请求串行。原生解码测试使用真实 MP3/FLAC 文件验证下载完成前首批 PCM、临时 EOF、完整 PCM 一致性、超前 seek、取消和失败；原生应用测试覆盖预加载复用及未完成缓存的持久化保护。真实平台的网络波动和实际点击到出声时间还需要在登录账号后实测。
