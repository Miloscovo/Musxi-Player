## 修复依据

QQ `GetPlaylistByUin` 的真实响应含目录号 1、2 的普通自建歌单，与目录号 201 的系统行并列。原代码把普通歌单硬编码为 `_0`，因此过滤了真实目标，并拒绝创建响应。现改为服务端返回的完整 `tid_dirId` 身份，写前重新取本人创建列表精确匹配；201..209 仍保守拒绝普通歌曲写入。普通目录号不再假定为 0，公开读取 DTO 的 `writable` 同时修正，系统行不宣称普通写权限。创建只接受服务端回显身份，再新鲜读回，不按重名标题推断。

QQ 公开歌单实测 `creator.musicid=0`，但 `creator.encrypt_uin` 与 `dirinfo.encrypt_uin` 有相同的非空身份。现支持受长度和字符边界限制的 opaque 身份，与当前账号及本人完整创建集合核对；两个回显同时存在时必须相同，空白、控制字符和冲突拒绝。没有按一次样本猜固定长度。公开目录号 203 是真实普通歌单，不套用本人系统写入目录的全部限制；201/205/206 仍拒绝订阅。

酷狗默认歌单带 `is_def=1`，可增删歌曲但固定名称。其云协议曾返回 `status=1/error_code=0` 并推进版本号，读回名称却没有改变，证明不能仅凭写响应宣称成功。新增 `systemDefault`，默认歌单、红心及非本人目标在改名前拒绝；默认歌单的歌曲写权限保持服务端原判断。对真正自建歌单仍要求完整原排序/标签/简介/版本，写后核对标题及非目标元数据。

`capabilities.reason` 是平台整体提示：QQ/酷狗为 `partial_support`，网易云为 `subscription_risk`；布尔值表示协议实现存在，不承诺每次请求均被平台接受。网易云的实际风控结果必须继续单独呈现。

## 可复用专项与恢复

必须指定测试类或方法，不能运行整个历史设备套件。所有真实写入需 `allowPlatformWrites=true`；改名额外 `allowPlaylistRename=true`，整单订阅额外 `allowPlaylistSubscription=true` 并传明确公开目标，多歌单额外 `allowMultiPlaylistWrites=true`，创建额外 `allowPlaylistCreate=true`。

- `PlaylistMembershipDeviceTest`：单普通目标添加/幂等/移除，精确核对原顺序和红心。
- `PlaylistMultiMembershipDeviceTest#qqTwoPlaylistsRemoveOneAndKeepOne`：两个现有 QQ 普通目标，验证同时添加与分别删除/保留。
- `PlaylistRenameDeviceTest`：酷狗/网易云改名并恢复；其他客户端把名称改为第三个值时保留冲突，不覆盖。
- `PlaylistSubscriptionDeviceTest`：QQ 目录只读诊断；QQ/网易云对原先未订阅目标往返，恢复完整账号歌单集合与本人内容。
- `PlaylistCreationDeviceTest`：最多一次 QQ 创建意图；手机私有 marker 已存在且缺 ID 时只输出 `UNKNOWN/createdAgain=false`，不再创建。
- `KugouRenameDiagnosticDeviceTest`：仅测试包内临时代理原 transport，输出固定字段结构、状态/版本及名称相等布尔，不导出请求、凭证、ID 或歌单名；finally 恢复 transport。

写前将实时 owner、目标和完整基线存入手机私有 `filesDir`，清理只撤回本轮新加的歌曲/订阅，改名只恢复本轮临时名；成功后保留 `restored` 记录。**本轮所有歌曲/改名/订阅待恢复记录为 0；另有 1 份 QQ 创建结果不确定 marker，不能与待恢复操作混为一类。** 新建测试歌单保留，不删除用户或测试歌单。保留账号、登录、设置和队列，没有退出、换号或清数据。
