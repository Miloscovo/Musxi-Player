# 本地音频、OPPO 取消与熄屏观察补验

2026-11-11，接续「Musxi 安卓开发261106」及 [11-10 追加验收](backend-local-followup-device-20261110.md)。设备为 PJF110 / Android 16。用户说明 CC 正在开发前端；本轮没有修改前端文件、覆盖安装主包、操作平台收藏或账号、重启手机或强制全机 Doze。没有真人听音。

## 包与证据

本轮设备主包始终是 11-10 安装的 debug 包，SHA-256 `62df3088b1a068912e92ce73c4b000ab0f34d55d3978748f3399599afa788426`。先用原设备测试包复验通知及复现 OEM 失败，随后只覆盖安装修正后的设备测试包。不能将这些设备结果记到 CC 正在修改的前端或新生成的主 APK 上。

材料在 `.local/artifacts/local-device-20261111/`，最终索引为 `final-summary.json`；内含各阶段日志、包与修改文件散列、清理结果及统一验证引用。源码完整验证与设备分项分别判断。11-10 追加轮的 `final-summary.json` 缺失，本轮没有补造旧轮通过结论。

## 两处修正

`LocalAudioFollowupDeviceTest` 原取消步骤只发一次返回；实测 OPPO 会先从测试文件夹回到 Download 上级目录，仍未取消选择。现最多逐级返回六次，每次确认当前窗口属于选择器、拥有活动及焦点状态，并使用其 displayId；收到真实结果立即停止。修正后专项通过。

`build.ps1` 的共享锁原来使用 Git 输出的中文绝对路径。GBK 终端把目录解码为既有乱码目录，UTF-8 终端则使用正确目录，两者因此取到不同锁。本轮发现与 CC 同时启动后，立即停止本轮构建客户端，确认 Gradle 取消，并仅停止本轮产生的 daemon；未停止 CC。改为 Git 相对路径加本机绝对路径解析。独立进程在 UTF-8／GBK 下都解析到正确目录，且均被同一把已持有的锁拒绝；证据为 `lock-probe-65001.json` 与 `lock-probe-936.json`。随后构建串行完成，没有覆盖安装生成的新主包。既有乱码目录未在本轮整理。

## 熄屏证据与剩余项

普通应用进程观察不使用 instrumentation 保活、额外唤醒锁或电池设置修改。USB 充电，标准 device-idle 为 ACTIVE；系统电源报告中 ExoPlayer 唤醒锁出现在 OPPO 的 `Restored Wake Locks`／代理相关信息中。前台播放服务仍在，AOSP 进程状态未标记冻结。上述是相关现象，尚不能确定为 OEM 挂起、音频静音样本策略或应用调度问题。

`background-pre-wake.json` 保留亮屏前的停更报告；`background-after-wake.json` 保留恢复后的进度与屏幕事件；`background-final.json` 记录主动 abort 和暂停。屏幕密码由用户手动解锁。没有把屏幕点亮后的采样拼成熄屏定时通过，也没有把观察器停更直接认定为音频停止。

下一轮应优先设计能区分硬件音频推进、应用调度及定时实际停止时刻的专项，使用可听但不扰人的样本，并与用户确认听音。长后台／Doze、整机重启、真实耳机蓝牙与来电、OPPO 目录选择和正式前端流程仍待验；不因本轮而增加平台写入或系统设置授权。
