## 首版行为（历史，自动规则由顶部B4契约替代）

原歌单某首明确不可播放时，保留原列表、歌曲位置和顺序，搜索另外已连接平台的候选。用户手动选择一项后临时用于本曲播放；播放结束继续原歌单下一首。页面无需跳离原歌单，明确显示“歌单平台”和“当前音源平台”。取消、跳过、上一首/下一首都由原队列统一处理，不进入候选搜索结果的播放顺序。

候选显示歌名、歌手、专辑、时长和平台；标题中的现场/重录等版本标记保留。未验证取流标为“待尝试”，只有成功取到官方标准音质后才算实际播放。当前跨平台使用标题加首位歌手搜索，每家首屏最多 10 首；平台优先顺序固定为网易云、QQ、酷狗，排除原平台与未连接账号，保留各平台返回顺序，不依网络完成先后随机排序。

候选列表准备好后开始 5 秒倒计时；用户在此期间点任意候选立即尝试，超时尝试列表中第一个同名候选。标题只做 Unicode NFKC、大小写与空白归一，保留版本后缀；这只能证明同名，不能证明同录音。没有同名项时不自动播放相关结果，仍可手选。取消、暂停、停止和导航使旧搜索/倒计时失效，不能迟到后自播；页面退后台后服务的既有倒计时继续。

替代候选若也明确无权限/不可用，排除已试来源后重新展示并计时，本曲最多尝试 3 个候选；无结果、耗尽或搜索失败时保留原队列并停止，提供重试原曲或下一首。网络/超时/账号失效等不触发换源链。记住映射、自动优选、跨平台偏好与分页搜索暂未实现。短期音频地址不落盘，每次检查两个账号归属。三平台登录扩大候选范围，不保证所有歌曲可播。

## 后端需要的变化

原队列仍为单平台，`QueueSources` 在当前 opaque ticket 下单独记录实际 sourceId/sourceGeneration。原条目保持 mediaId 与索引；实际来源用于取流、媒体信息、授权校验与失效重取。原队列账号失效清空队列；当前替代源账号失效停止播放并保留原队列。离开当前项后恢复其原始来源，下一首沿原队列，回播时重新检查来源。

候选搜索、选择、取消和切歌必须有请求代数，旧候选或旧取流结果不能恢复已停止/替换的歌曲。不要替换整个原队列，不向前端返回凭证或媒体地址。现有不可播自动跳过规则需要在换源选择等待态下协调；网络错误不直接触发跨平台权限替换。

## 开发优先级

1. 安卓基础使用验收与必要修复：锁屏/通知控制、耳机断开、焦点、真实断网重试、前后台/页面重建。
2. 换源最小闭环：单曲失败→搜索候选→用户选择→临时播放→回原队列下一首；验证取消、快速切歌及账号失效。
3. 整理统一状态、命令和样例，再交 cc 做正式前端接线。cc 可提前设计账号页、曲库和播放器布局，但换源相关接口此时不冻结。

本文件更新当前产品范围；历史“手动选源/尚未实现”记录以本轮增量为准。只使用账号实际可取得的官方完整音频，拒绝可识别试听；不会改变平台权限。实际构建、设备与用户听音结果须分别记录。

## 本轮验收与媒体会话修复

| 路径 | 实际证据 |
| --- | --- |
| 真实自动与手选 | QQ 原 7 项歌单 AIZO 拒绝后准备 20 候选，5 秒自动选网易云；用户确认声音和歌曲正确。手选第二项也已播放。三平台固定 AIZO 搜索各返回 10 项，不代表全部可播 |
| 原歌单接续 | 原 QQ mediaId/索引 0 不变，网易云来源可跳到约 162488/215954ms 后继续；曲尾前 1 秒 seek 后等待自然结束，回原 QQ 索引 1、automaticTransitions=1、选源状态 NONE |
| 暂停、取消、导航 | 候选中 pause/cancel/stop 后超过旧截止不自播；next 进入原 QQ 下一首，旧 timer 不覆盖。模拟权限错误晚 2 秒到达，先暂停仍不自播。暂停已成功替代音频保留来源标识，resume 可继续 |
| 连续失败 | debug 模拟原曲及 3 候选共 4 次权限失败后 FAILED，保留 7 项队列；再等超过 5 秒，resolve 仍为 4。没有剩余同名时通过手选推进验收，不能把相关歌曲当同名自动播；重试先恢复 QQ 原来源 |
| 系统控制 | 普通 MediaController 的直接 play（不先 prepare）可恢复原曲请求；真实 STOP 立即取消待选，超过旧截止保持安静。没有屏蔽通知控制器或系统 STOP |
| 页面与后台 | 服务计时独立于页面，HOME 后按时选中网易云；该次实际取流 NETWORK，保留原队列停止，前台显式重试成功。已开始的替代音频经页面重建/HOME 后短时继续；不据此宣称后台每次起播均成功 |

连续候选失败曾稳定触发来自 legacy 媒体会话通道的 STOP，不能归咎于用户误触。清除加载或仅隐藏错误均未解决。最终使用 `ForwardingSimpleBasePlayer` 将服务正在处理的权限/不可用错误统一表达为等待播放（BUFFERING/播放意图仍在），getter 与事件一致；真实底层错误继续供恢复判断，终态通过原错误/失败状态反馈。该复现消失，四次失败上限与主动 STOP 分别通过；未确认设备系统为何发送 STOP，不写成已定位系统源码根因。直接 play 补 prepare、任务移除按服务播放意图判断，均经只读复审。

自动检查为 142 项 JUnit、0 failures/errors，六个 Android 模块 Lint 0 errors；debug APK v2 签名及 release 清单调试入口隔离通过。正式 UI 尚未实现，接口和状态示例见 frontend-contract.md；未做真实换号/自然过期、长时 Doze、多设备、逐首或整曲逐秒验收。已连接平台扩大候选范围，同名不证明同录音。账号/缓存保留，不改平台歌单，不发布或提交。
