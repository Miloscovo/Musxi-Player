## P0 · 账号头像（v0.2 发布前要有）

产品负责人 2026-11-01 18:50 定：登录的账号要完整、正确地显示该平台的头像；没登录显示默认头像。

前端已就绪（CC）：
- `AccountProfile` 已加可空字段 `avatarUrl`（`core/.../account/AccountModels.kt`，默认 null）。请直接填值，不要再声明一次。
- 界面：有昵称的行显示 `avatarUrl` 指向的图片（40dp 圆形，Coil 加载）；加载中或加载失败时显示昵称首字；没登录（含登录过期）显示默认头像。`meAccountRowOf` 只在行有昵称时取 `avatarUrl`。

要做：
1. 三个平台确认身份时取回用户头像地址。`PlatformDrivers.kt` 的 `Identity` 加头像字段，各平台驱动从现有的资料或身份接口读取；`AccountRepository.profile()` 把它放进 `AccountProfile.avatarUrl`。持久化的身份也带上它，冷启动后不用等网络就能显示；资料刷新时更新。
2. 地址校验：只放行平台自己的图片主机，https（http 可升级），不带凭据。现有 `ArtworkPolicy.sanitize` 会拒绝带查询参数的地址；QQ 的头像可能在别的主机上并带查询参数。请按三个平台真实账号返回的地址核对，必要时单独写一个头像策略，不要放宽 `ArtworkPolicy` 本身。
3. 尺寸：显示为 40dp（约 120px）。平台支持按尺寸取图时，取 120–200px 的版本，不要原图。
4. 隐私：头像地址能识别用户，按昵称同等处理：不进日志、诊断导出和 DUMP，`AccountProfile.toString` 保持脱敏。
5. 只有头像变化不算换号。凡是比较 `AccountProfile` 来判断"账号变了没有"的地方，改为比较 platform + id，避免头像刷新触发账号代次变化或清缓存。

验收：单测覆盖三个平台的解析与校验（含被拒的地址）、持久化往返、头像变化不改变账号代次；真机上三个平台登录后，"我的"页和账号子页显示真实头像，退出后变回默认头像，重启后不等网络就显示。

## P1 · 酷狗曲库短暂显示"0 个歌单"

现象（2026-11-01，PJF110）：17:54 酷狗曲库显示 3 个歌单；约 17:59 起标题变成"0 个歌单"，页面写"这个平台还没有歌单"，"继续播放""我喜欢""最近播放"都不见了；18:14 进程重启后恢复 3 个歌单。其间应用日志没有报错，这部分界面代码本轮没有改。

界面只在读取成功且列表为空时才写"这个平台还没有歌单"，所以疑似某次刷新拿到了空结果（或把失败当成了空结果），覆盖了已有缓存。请核查：刷新失败或异常的空响应会不会覆盖非空缓存。如果平台确实返回了空列表，建议不立即覆盖非空缓存，保留旧数据并标记待重试。是否采纳由你判断，写明理由。
