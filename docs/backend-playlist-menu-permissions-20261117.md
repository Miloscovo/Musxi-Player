# 歌单长按反馈与酷狗操作权限查询修复

2026-11-17。用户要求去掉大封面歌单长按时覆盖封面及文字的半透明圆角反馈，保留震动与现有浮卡风格；同时报告酷狗浮卡“操作权限读取失败”，无法进入改名／删除，QQ 与网易云正常。本轮不提交推送发布，不真实创建、改名、删除歌单或改收藏。

## 长按反馈

网格歌单继续把封面、标题及歌曲数作为统一点击／长按区域。关闭该区域的默认 indication，通过现有 `rememberHaptics` 发出一次 `Haptic.LONG_PRESS`，并关闭框架自带长按震动以免叠加。沿用现有封面、字体、布局与 `AnchoredMenu` 材质／动画，不增加缩放、边框或蒙层。短按继续打开详情；列表模式的三点及拖动把手不变。此方式与现有收藏按钮使用的无水波纹长按和统一触感入口一致。

## 酷狗实机定位

手机只读权限查询的三条非喜欢目录行均返回 `incomplete`，失败发生在远端完整账号目录扫描，尚未进入改名／删除。不是菜单遗漏了已返回的权限，也不是将两个平台的权限套给酷狗。

测试包中固定 `/v7/get_all_list` 只读 schema 探针记录字段类型及行数，不输出账号、歌单 ID／标题、令牌或响应原文。实测 pagesize=100 和 30：第一页均为 4 行 `info` 数组，不含 total/count；第二页均为 `info:null`、lists 缺失。因此并非 100／30 页长不一致，而是实际终页协议与严格扫描只接受空数组的规则不兼容。普通目录读取早已允许后续 null 页，权限、改名和删除使用的严格扫描却拒绝了相同响应。

此前删除功能和单次实机结果仍保留，见[正式删除后端](backend-kugou-playlist-delete-20261113.md)。不能把此前通过扩大为当前账号协议下的所有菜单操作已验收。

重连后，原权限修复包只读查询已成功，且实机确认两种页长的 `total_ver` 均合法、稳定。但两条普通自建行均返回可改名、不可删除。追加不含账号／标题的字段摘要证实：默认收藏／喜欢行分别显式 `is_def=1/2`，两条普通行省略整个 `is_def` 键；四行均带与当前 session 严格匹配的 `list_create_userid`。这是第二个兼容点：生产门禁原要求显式 0，而旧删除探针的普通行判断没有该条件，不能用旧探针成功替代生产门禁验收。

生产解析现在保留显式 `is_def=0` 的原规则；只有键完全缺失时，才额外要求 `is_edit=1`、创建者和 session ID 均为规范正十进制安全整数且完全相同。显式 null、空、未知及系统标志不会进入兼容路径。无 session 的纯解析不推断归属。写前完整重读使用同一规则，归属改变会拒绝，改名元数据不能替代删除权限。

## 兼容条件与保护

严格扫描只在以下条件全部满足时接受这个 null 终页：

- 前一页是非空短页，当前为后续页，按固定步长连续读取；
- 根响应成功，明确为 info:null，lists、total、count 均缺失；
- 从首页到当前页都带合法且相同的 total_ver；
- 原有账号代次、超时、行数、重复 ID 和已知 total 一致性检查继续成立。

首页 null、满页后直接 null、字段缺失／冲突、版本缺失／非法／漂移仍失败。没有总数的协议仍依赖服务端正确响应；客户端不能绝对证明服务端未截断。仅在完整扫描结束后判断目标缺席，普通本人／系统默认／喜欢／收藏的行权限检查、改名元数据、写前重验、最多一次写入和写后核实均保留。没有把所有 null 直接视为空目录，也没有用目录行的展示分类代替服务端权限。
