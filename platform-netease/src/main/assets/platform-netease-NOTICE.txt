2026-11-06 ordinary playlist removal, creation and renaming adapt module/playlist_tracks.js, playlist_create.js and playlist_name_update.js from the same pinned MIT source.
Whole-playlist subscription additionally adapts module/playlist_subscribe.js,
register_checktoken_v3.js and util/request.js from that pinned source. The Android
adapter uses a fresh HTTPS v3 token; the upstream subscription module selects v2,
so real-account acceptance of the v3 substitution remains unverified. No remote
JavaScript, browser verification SDK or new runtime dependency is bundled.

Later on 2026-11-06, the incompatible v3 default was removed after platform rejection
and review of the same pinned playlist_subscribe.js, register_checktoken_v2.js and
util/request.js. Writes now require a compatible SDK-v2 provider, currently unavailable.
No Watchman SDK, browser fingerprint emulation, remote script or dependency was added.

2026-11-07 optional native YRC additionally adapts module/lyric_new.js at the
same pinned MIT revision: /api/song/lyric/v1 via the existing phone-local EAPI
transport. Valid YRC uses its own primary line/word timeline and matching ytlrc;
ordinary lrc/tlyric and the earlier lyric.js request remain safe fallbacks.
YrcLyricsDecoder is independently implemented with bounded UTF-16 word ranges.
MeiloX's fixed bc038c9e9a01f37484a13295b2c3a8c3e44d8804 YRC parser/tests were
design references only; no source, resource or dependency was copied from them.
Existing Binaryify MIT license and Musxi GPL notice remain; no runtime dependency.
The earlier v3 paragraph records the previous implementation, not the current default.
